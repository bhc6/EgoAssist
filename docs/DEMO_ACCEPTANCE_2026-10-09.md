# 2026-10-09 完整演示修复与验收

本次目标是能够完整、流畅地演示产品功能，范围为本机/团队现场 Demo。使用方式、项目逻辑和讲解路线见 [演示指南](DEMO_GUIDE.md)。没有开展工业化部署改造。

## 发现与修复

1. **连续回答串题。** 默认模块化语音通道只积累助手输出，没有同步新用户消息；工具和任务状态正确也可能复述旧问题。现在从持久日志生成预算内上下文，在请求进入回答队列时固定快照，覆盖音频、文字、Omni 的文字适配和视觉答案交付。系统指令放在会话消息之前，保留用户/助手顺序。异步工具只追加本次已提交回执，不重新读取未来输入。
2. **退出 Skill 后提及旧任务。** 将本次已接受的 Skill 变更传给回答模型，退出现场记录时不再根据更早的通勤任务猜测退出对象。提示词也明确要求新话题不能继承旧物品或编造草稿细节。
3. **观察结果因格式差异整帧丢失。** 模型曾把 `uncertainties` 输出为字符串。提示词明确数组格式，适配层将单条文字保留为单元素数组。视觉证据仍必须为数组；任务校验和来源权限没有放宽。
4. **新提醒目标受到旧提醒文本干扰。** 从模型的画面对比上下文移除旧的提醒/提问文字，并按当前目标来源过滤提醒历史。持久审计仍保留原始候选、抑制原因和播放记录。
5. **局部删除使无关证据快照失效。** 历史删除原来清空整个账户索引。现在先按原始来源校验快照，再重建索引并保留有效快照。被删除文本不留在旧 SQLite/FTS 页中；账户/记忆整体删除仍完整失效缓存。新增 HTTP 层回归验证删除范围、无关快照保留及缓存不残留测试原文。
6. **缺少统一演示入口。** 新增 `scripts/demo.py` 的 `check/start/verify`，统一演示配置、独立数据根目录和串行验收。新增日/周/月日记验收，使用新建示例补记，摆脱旧个人日志和历史输出目录依赖。任务验收扩展到全部固定任务入口。

快速模型 `qwen-flash` 在上下文修复后，面对信息不足的取物说明请求仍出现编造。对同一真实请求进行了 `qwen-plus` / `qwen3-max` 对照：前者询问缺失信息，后者给出不捏造物品的通用句子。专用演示入口选择 `qwen3-max`；常规入口和 `.env` 不被修改。有限样例不能证明模型永远不会出错。

## 保留的失败记录与范围

- `skills01` 原脚本只检查路由和状态，报告通过，但人工审阅发现复述及串题。`skills02` 出现 JEV 超时；`skills03`–`skills05` 仍有泛化或编造细节。后续增加供应商消息、退出对象及回答语义断言，保留旧结果。
- `ambient01` 因不确定性字段类型错误拒绝帧；`reminders01` 因脚本尝试编辑已禁用的提问设置失败；`reminders02` 出现旧提醒候选，播放校验抑制了错误播报。最终 suite 的观察与提醒验证通过。
- `tasks01` 使用工具关闭配置，参考资料未执行；开启工具后的真实 PDF 验收通过。`lifecycle01` 暴露无关快照被误删除，修复后通过。
- 跨天测试使用合成日期输入，语音使用合成音频或标注来源的重放，视觉使用视频采样。日记仅覆盖两条补记所在的一天。没有把它们作为真实生活长期实测或眼镜硬件验收。
- 本机未配置 Temporal、人工求助 webhook、LiveKit 凭据。未来定时任务、外部消息和 LiveKit 传输属于条件能力；核心演示使用 WebSocket 和画面触发提醒。

现场仍需用实际麦克风、摄像头和播放设备试用，确认设备授权、收音、回声和现场网络。核心软件演示流程已有上述可复现验证。

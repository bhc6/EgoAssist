# OpenRouter Decisions：接入与中文窄判断实测

后续已提供[生产路由接入](DECISIONS_ROUTER_2026-09-24.md)。本文保留最初五问题的离线实验协议与原始结果，不将它与完整路由成绩混合。

2026-09-24。用户提供的 `OPENROUTER_API_KEY` 和 `POST https://openrouter.ai/api/alpha/decisions` 已实际连通。请求模型 `typesafe/jev-1.13`，示例响应返回版本 `typesafe/jev-1.13-20260917`，provider 为 TypeSafe。

## 当前交付

- `egoassist/eval/openrouter_decisions.py`：独立研究客户端，支持 `noul`、`choice`、`score`，校验字段、数值范围、选项与分布；返回原始响应、请求 ID/模型/usage（供应商有返回时）和耗时。不执行任务、控制声音或写入记忆。
- `egoassist/prompts/decisions_research.json`：五个中文窄问题，判断说话对象、声音控制、任务控制、明确记忆意图和提醒请求。自然语言策略在提示词资产中维护。
- `scripts/benchmark_openrouter_decisions.py`：复用已有路由研究的 12 个开发案例，每次调用前使用冻结的问题定义；原始请求、输出和评分保存在全新输出目录。无答案缓存或自动重试；401/402/403/429 保留记录并终止后续请求。认证 header 不写入审计。
- `.env.example`：加入 `OPENROUTER_API_KEY`。加载顺序与项目一致，进程环境优先于 `.env`。

当前入口仅用于离线实验，实时 `SemanticTurnRouter` 仍使用原协议。Decisions 输出回答的是预先定义的有限问题，尚未承担原路由的原话提取、记忆原子生成、来源/目标 ID 选择、时间参数提取、Skill 选择和复合任务完整拆分。

## 真实接口预检

原样使用用户提供的英文客服示例（去除 Markdown 链接及反斜杠转义），一次请求返回 HTTP 200，耗时 1011.1 ms：

| 类型 | 实际返回 |
| --- | --- |
| `noul` | `is_urgent.noul = 0.95` |
| `choice` | `department.choice = billing`，分布 billing 0.88 / technical 0.12 / sales 0 |
| `score` | `frustration.score = 1.04`；供应商 legend 为 0=Calm、1=Frustrated、2=Very angry |

这次验证了接口和三种类型格式，不是中文路由质量评测。`score` 对应有序等级上的数值，不能当成 0–1 的概率。供应商返回的概率、confidence 与用户授权或事实真实性不同，本项目没有完成校准。

## 中文开发集结果

运行前冻结题目、期望值、问题定义与代码哈希。使用 `verify_router_latency.py` 已有的 12 个合成中文开发案例，连续运行三遍，共 36 次调用；无新留出题目，也未指定 seed。输入仅含原话、未知说话人状态和必要的简短任务背景；期望标签不传给模型。模型需要回答五个窄问题，不能与历史完整 Qwen 路由的通过率或耗时直接比较。

| 指标 | 实测 |
| --- | ---: |
| HTTP/类型校验成功 | 36/36 |
| 五字段全部符合冻结期望 | 32/36（88.89%） |
| 说话对象 | 36/36 |
| 声音控制 | 34/36 |
| 任务控制 | 36/36 |
| 明确记忆意图 | 34/36 |
| 提醒请求 | 36/36 |
| 有效响应耗时中位数 | 355.815 ms |
| 主实验响应 `usage.cost` 求和 | 0.001571724 |

耗时为客户端请求到收完响应并完成校验，包含网络，不是模型纯推理时间，也不含 ASR、上下文准备、业务执行或声音输出。成本直接汇总供应商响应字段，不是账单核销结果，不含预检。三次重复没有增加独立案例数；没有记录服务端缓存命中率，不能将重复延迟视为冷请求基准。

`noul` 在本实验按 >=0.5 计算二分类标签，这只是预设开发评分阈值，未校准，不接业务执行。`choice` 使用返回的选项，分布与 confidence 原样留存。

## 四次不一致及其含义

1. **复合提醒两次误归为显式记忆保存。** “五分钟后提醒我关烤箱，现在告诉我烤土豆该用多少度”：提醒判断正确，但两次 `memory=save`，冻结标签为 `none`。保存概率分别 0.52、0.51，接近边界。提醒任务的持久化不应自动变成用户授权保存个人长期记忆；本次未触发任何写入。
2. **任务暂停两次在 `none` 与 `continue` 间不一致。** “把当前做菜任务暂停，但你可以继续回答问题”：三次都正确判断任务暂停；两次声音控制为 `none`，冻结标签为 `continue`。这是允许继续与明确要求恢复的语义边界，不能直接称为错误停播——三次均未选 `stop`。保留严格原分数，不在看到结果后修改标签使其通过。后续应预先定义多种合法输出及当时播放/静音状态。

否定停播、引用别人的“别说了”、对他人说话、询问步骤是否完成与否定完成，在本轮均符合期望。这些是已暴露的短文本合成案例，不能证明复杂自然语音、多人环境和未知指代的泛化性能。

## 与现有系统的关系

这个接口符合“模型判断语义，代码管理流程”的职责分工。适合继续试验为可校验的候选判断，例如区分查询、明确保存、纠正和遗忘意图；实际入库仍需检查账户、范围、来源、目标卡片、版本和明确授权。

目前不据此替换完整实时路由，原因是尚未覆盖完整协议，也没有同输入、同输出任务的当前模型对照。下一步优先是增加**新的**成对样例：提醒与保存区分、引用与否定、句内自我修正、当前/历史对象、他人发言、带已有静默状态的恢复请求。先冻结可接受输出集合，再比较错误控制率、漏判率、拒判覆盖率、延迟和真实成本。置信度阈值需要独立校准，不能通过提高阈值就假定安全。

## 复现与证据

```powershell
.\.venv\Scripts\python.exe scripts/benchmark_openrouter_decisions.py --output outputs/openrouter-decisions-new-run --repeats 3
.\.venv\Scripts\python.exe -m pytest tests/test_openrouter_decisions.py -q -p no:cacheprovider
```

输出目录必须不存在。需要有效 `OPENROUTER_API_KEY`，会产生真实供应商调用。退出码 0 表示全部冻结字段匹配，1 表示存在模型不一致或一般调用失败，2 表示访问/余额/限流错误提前终止；失败不会被转换成否定判断。

# 产品与独立机制研究的边界

EgoAssist 既是智能助手产品，也可以作为记忆研究的工程基座。新机制实验由独立项目 **MemoryMechanismLab** 负责；在当前本地工作区，两者是 `DEMO` 下的平级目录，各自拥有依赖、版本、测试和发布入口。

产品保留原文存储、SourceIndex、Timeline、LongEvents 及观察/交互/记忆链路。研究项目负责实验组、公共候选合同、预算、运行冻结、评分和统计。产品不导入研究包；研究默认模式也不要求产品安装。

复用产品能力时，通过显式离线 adapter 接入指定源码快照和 Python 环境。当前 adapter 实际调用 SourceIndex，在临时研究目录导入当前查询可见的原文前缀，将公共 FTS 候选交给四组 G/V 选择器。产品账户、实时服务和密钥配置不属于这个实验入口。

同一实验内四组必须共享同一个基座、相同输入和表示；跨基座结果另作鲁棒性分析，不能把候选提名差异解释成机制增益。自动事件提取/长期事件适配尚待后续实现，不能把 SourceIndex 桥接说成完整产品记忆机制验证。

既有 `egoassist/eval/`、评测脚本和日期文档保留为历史复现/回归材料。2026-10-01 协议中“新 runner 放在本产品仓库”的建议路径已由独立研究项目替代；不要在两个仓库继续维护两套新的机制运行器。旧实验结果和旧路径没有搬迁，也不因此变成独立测试集。

发布时分别从产品和研究目录构建。研究 wheel 不包含本产品；使用产品条件复现实验时另行记录产品代码及环境。工作区内数据、缓存、历史产物和第三方 checkout 不随任何源码包整体发布。

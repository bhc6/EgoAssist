# 已有实验结果与重要案例汇总

整理日期：2026-09-23。本文汇总仓库中已有的研究评测、真实链路验收和重要失败记录，供后续记忆机制研究选题与对外介绍使用。这里的“通过”按各报告原有协议解释，不把工程回归、模型评测、合成压力检查和产品演示合并成一个效果指标。

## 先读结论

1. **已验证的系统能力是有来源、可纠正、可恢复的个人记忆工作流。** 记忆记录保留来源与版本关系，用户明确纠正后旧版本退出 active，新版本携带 supersedes；历史证据可供回答、观察比对和周期整理使用。真实浏览器/模型链路已有相应案例，但这证明链路行为，不等于记忆内容始终正确。
2. **EgoLife 检索评测尚未证明稳定的准确率提升。** 语义向量扩大了部分目标时刻候选覆盖，排序变化也能影响最终回答；但样本只有一位参与者的 30 道已暴露题目，区间较宽，证据支持度低。目标时刻重叠只是代理量，不是完整相关性标注。
3. **需要把正确答案与有依据的正确答案分开。** 2026-09-14 的 C 组答对 29/90，但只有 6/90 同时被评审判为正确且有支持；来源复测 S 组答对 29/90，其中 7/90 同时满足两项。Judge 也未经人工复核，故联合指标仍只是诊断。
4. **日记与长事件已证明可处理、可审计、可恢复，尚未证明长期内容质量。** 演示来源并非真实连续生活记录；3000 条边界测试是合成测试，不能作为长周期记忆质量成绩。

### 结果中最值得复查的单题

- **#121「下午我们有什么活动」**：原文来源路径三次选中“跳舞”，与标准答案一致，评审认为原文支持。这是可讲解的正向来源证据案例。
- **#400「为什么我说推车倒着推」**：原文路径三次回答“因为倒着推稳定”，与标准答案一致且评审找到原话支持。
- **#230「上一次用手机拍照拍的是谁」**：原文路径相较 Timeline 仍出现当前事件与上一次事件混淆，三次输出均未命中。说明时间排序与事件指代仍是记忆机制的关键难点。
- **#223**：原文路径三次猜中选项，但材料没有说明是谁摆放用具。它是“答对不代表检索有证据”的具体反例。
- **#373**：来源评审把一天中的 43,908 秒（约 12:11）误读为凌晨。本轮原样保留 Judge 结果，说明自动证据评审本身也需要人工校准。

这些题目都已暴露，后续只能用于回归与错误分析，不可再作为新留出集。

## 实时链路与工程验证

- [异步与多链路运行](ASYNC_LATENCY_2026-09-10.md)：双问题受理回执约 56.6/56.8 ms，视觉请求重叠；首个后台答案发布约 2662 ms，第二问首音频约 2932 ms。均为少量桌面浏览器运行，不是硬件端延迟承诺。
- [语音延迟诊断](VOICE_LATENCY_2026-09-18.md)：旧重负载会话两轮从输入持久化到首音频约 24.99/28.17 秒，其中包含 3 万余输入 token、排队和上下文准备；修复后新轻负载会话首音频 1.406/1.799 秒。两种负载不等价，不能宣称原场景已整体降到 1–2 秒。
- [路由延迟优化](ROUTER_LATENCY_2026-09-19.md)：冻结日志局部上下文读取中位数从 321–778 ms 降至约 1.4 ms；8 条真实日志隔离路由回放均分类，路由中位 1361 ms。模型 A/B 为 max 12/12、flash 5/12，因此保留 max 默认。回放无执行副作用，8/8 不代表分类正确率或现场正确率 100%。
- 工程全量回归用于检验接口契约、持久化、恢复、权限和边界行为，不衡量记忆算法质量。2026-09-23 当前主线基座全量为 **781 项通过**（3 条既有 aiohttp warning）；日记、路由等历史报告内的 455、670、749、774 等是各自当时快照，不能累加或替代当前总回归。

## 失败模式清单

1. **候选没召回与最终排序是两种损失。** 扩大候选预算能找到更多目标片段，但最终 top-5 仍可能错过；仅做语义重排无法救回候选池外的来源。
2. **安全门会降低召回。** 17/22 条旧来源被指代检查标为需澄清，覆盖 85 道旧题；这暴露解析损失，但没有证据支持删除身份约束。
3. **正确率、依据和时间定位不一致。** 强制选择会让模型猜中却无来源支持；时间戳重叠不能替代答案证据相关性。
4. **长上下文有成本且会引入歧义。** 原文路径显著增加来源数量与 token；长会话路由又出现大上下文与排队。需要等预算或等 token 实验，不能只比较答题率。
5. **事件、身份和状态仍需显式边界。** 当前/过去事件混淆、谁说的/谁做的、任务已交付但未完成、长暂停拆成两个事件，均在保留报告中出现。
6. **自动 Judge 与测试夹具也会失败。** 时间单位误读、引用检查过严、浏览器状态等待错误和旧帧过期都曾导致失败；原失败记录应保留，不能只展示最后成功轮。

## 对外介绍时可用的准确说法

> EgoAssist 把实时观察、对话与长期记忆连在一起：保存可追溯的个人经历，允许用户纠正，并在后续问答和回顾中引用原始来源。我们已经验证了纠正、恢复、并行处理和证据展示的真实产品链路；在 EgoLife 小样本检索评测中，语义检索补回了一部分词法路径漏掉的候选，但端到端准确率优势还不稳定，证据支持和长时间事件理解仍是研究问题。

避免说“已证明长期记忆让回答更准确”“语义检索稳定优于基线”“日记验证了一个月真实生活”“声纹身份准确率已提高”或把 781 项测试称为记忆效果分数。

## 下一轮科研优先级

1. **建立新的、未暴露的带证据标注集。** 以事件/问题为单位标注足以回答问题的来源、时间范围、说话人/对象及可接受的多跳证据；按真实视频或参与者切分，避免同日近邻泄漏。
2. **先评候选与证据，再评生成。** 分开报告候选召回、排序指标、答案准确率、回答覆盖率、人工证据支持度和时间/身份错误；LLM Judge 只作为辅助并抽样人工复核。
3. **做等预算消融。** 固定同一问题、硬约束、回答模型和上下文 token 上限，对照 Timeline、BM25、dense、RRF、原文片段/相邻事件窗口；把索引构建成本和在线延迟另报。
4. **优先研究记忆语义结构。** 针对时间纠正、当前与历史事件指代、人物归属、状态演进、来源冲突和多跳关联建立成对反事实案例，再用新未见参与者做最终确认。
5. **日记与长事件暂作独立质量线。** 建立人工标注的事件边界、重要事实保留、矛盾更新和遗漏率数据，再讨论周期性建议是否有用。

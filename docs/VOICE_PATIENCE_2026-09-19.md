# 优先语音与停顿等待

- 原生麦克风的服务端结束静音阈值由 650 ms 改为 1200 ms，可通过 `EGOASSIST_SPEECH_END_SILENCE_MS` 在 300–3000 ms 内设置。语音开始的打断逻辑保持原样；这里只延后结束判断。
- 无音频证据的旧转写回调默认合并等待从 250 ms 改为 600 ms。原生音频使用服务端 VAD，不再额外叠加该合并时间。
- 路由明确优先为面向助手的普通请求选择 speech。明确文字请求、安静权限、停止要求和他人对话继续生效。“等一下，我还没说完”选择监听而不抢答。
- 增加 session.update 日志中的实际静音阈值；配置改变后重新建立实时连接生效。

验证：91 项相关测试通过（`outputs/voice-patience-20260919-tests.xml`）。真实模型的普通提问、只用文字、等待说完、对他人说话四例均符合预期（`outputs/voice-patience-20260919-routing.json`）。

真实 TTS 合成两段提问，中间插入 800 ms 静音，经产品 WebSocket 和真实 ASR/VAD 处理，只有一条完整 turn，随后生成语音回答。日志、音频与实际配置在 `outputs/voice-patience-20260919-real-r1/`。这是合成音频回放，不是物理麦克风测试；不能保证任意长停顿都合并。结束等待增加约 550 ms 是本次有意采用的耐心交互取舍。

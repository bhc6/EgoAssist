# 默认关闭工具调用

2026-09-26，按用户要求暂时关闭模型工具调用，已启用到本地 8770。

## 可用性核对

普通未加载技能的会话，平台工具列表本来就是空的。装配技能原本有本地 `show_reference`，可展示任务授权的参考资料；它不是外部联网工具。`set_timer` 只有 Temporal 工作器可用时才开放；人工求助需要配置连接器，内置技能中的旧本地回执只属于演示。本地未配置 Temporal 地址及人工求助 webhook。因此不能将之前的状态概括为“全部工具都不存在”，也不能把关闭工具模型描述为每句问候都会减少一次 Max 请求：原实现只有存在可执行工具时才调用工具选择器。

## 当前行为

`EGOASSIST_TOOL_CALLS_ENABLED=0` 为默认值，示例配置同步更新。

- 不实例化 `ToolModel`，不进入 `qwen3-max` 工具选择循环。
- 技能工具状态显示“工具调用已关闭”，可执行声明过滤为空；Omni 也不会收到可执行工具声明。
- 实时工具回调及 `/api/tools/execute` 均在执行前拒绝，旧 origin 携带的工具声明不能绕过开关。
- 语义路由中的展示参考资料分支只返回不可执行原因，不创建工具调用或执行回执。用户手动浏览已有资料的页面能力保留。
- 诊断接口 `configuration.tools.enabled` 显示实际配置。恢复需显式设置为 `1` 并重启；保留原工具实现和历史审计。

本开关针对模型工具调用及通用工具执行接口。三链路中的记忆处理、日记归档、观察提醒，以及既有独立工作流接口不属于该工具选择循环，未删除。JEV 仍负责交互判断；视觉模型按现有条件工作；复杂结构化解析或日记生成仍可能调用 Max，不能将本改动理解为删除所有 Max 调用。

## 验证与部署

新增开关回归分别检查默认关闭和显式开启：关闭时加载装配技能仍无工具声明、不创建工具模型，旧声明回调和直接 API 均阻断，普通问候仍提交回答。既有工具生命周期测试显式开启开关，继续检查来源、代际、更正与恢复约束。

[隔离真实浏览器](../outputs/tools-disabled-20260926/browser/acceptance.json)及[正式服务浏览器](../outputs/tools-disabled-20260926/production/acceptance.json)均加载装配技能，发送“你好”和“七加八是多少？只回答结果。”。两次均有文字和语音，计算回答 15；日志中没有工具请求、工具选择或工具执行事件，直接工具 API 被拒绝。正式服务首音 1282.4 / 1220.4 ms，仅为单次验收，不是前后性能对照。问候仍带装配技能引导，这说明本轮未解决所有技能提示词对普通聊天的影响。

初轮全量检查 904 项通过、2 项失败，原因是两项原工具测试尚未显式启用新开关；调整测试前提后两项所在模块 6/6 通过，证据保留于 `outputs/tools-disabled-full.log` / `outputs/tools-disabled-optin.log`。

最终全量回归 **906 项通过**，耗时 81.66 秒；3 条警告为 aiohttp WebSocket 超时参数弃用提示。结果保留于 `outputs/tools-disabled-final-regression.log`。

[部署记录](../outputs/tools-disabled-20260926/release/restart.json)：核对进程后正常退出，等待数据根目录锁释放，原入口启动，健康检查 200。已有页面需刷新或重新连接。未删除技能、记忆或原工具记录。

复现：`python scripts/verify_tools_disabled_browser.py --output outputs/tools-disabled-new`，或附加 `--base-url http://127.0.0.1:8770` 验证正式服务上的隔离账号。

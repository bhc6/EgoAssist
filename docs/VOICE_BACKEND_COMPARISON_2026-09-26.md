# Omni 与模块化语音链路真实对照

结论：模块化链路已通过修复瞬时 JEV 失败后的真实复测，现作为正式默认后端。第二轮 12 次问答与 2 次语音停止全部通过；模块化首音频中位延迟约 2916 ms，Omni 约 3171 ms，完整输出中位数约 3225 ms 对 3291 ms。Omni 仍可显式切换用于回归对照。

## 方法

基于 `076c722` 的运行代码，使用真实供应商，在独立运行目录测试，未修改正式服务配置。合成语音作为输入，以相同的 16 kHz PCM、100 毫秒音频块实时发送。包含完整应用路径：分段/识别、JEV、上下文处理、回答、语音输出。没有画面，避免视觉路径干扰。

- Omni：`qwen3.5-omni-flash-realtime`，语音结束静默阈值 1000 毫秒。
- 模块化：本地 VAD 静默阈值 660 毫秒 → `qwen3-asr-flash` → JEV → `qwen-flash` → `qwen3-tts-flash-realtime`。
- 两个问题，各重复三轮，交错后端顺序，共 12 次完整问答。问题为“七加八”及两段语音之间插入 500 毫秒静音的“十九加二十三”。
- 额外各测一次长回答期间语音说“助手，先别说话了”。
- 每次新建会话；计时排除连接建立，包含首次回答的真实开销。起点是输入 PCM 结束时刻，终点为 WebSocket 收到相应事件。

## 第一轮结果

| 指标 | Omni | 模块化 |
| --- | ---: | ---: |
| 正确回答且收到音频 | 6/6 | 6/6 |
| 输入结束到识别文本，中位数 | 1212.2 ms | 1221.5 ms |
| JEV 分类，中位数 | 928.2 ms | 944.1 ms |
| 回答请求到首音频，中位数 | 803.9 ms | 585.8 ms |
| 输入结束到首音频，中位数 | **3281.9 ms** | **3000.8 ms** |
| 输入结束到首音频，范围 | 2967.2–3375.1 ms | 2823.6–3069.6 ms |
| 输入结束到完整输出，中位数 | **3359.4 ms** | **3590.0 ms** |
| 停止口令结束到服务端 playback_stop 事件，单次 | 2403.1 ms | 2109.8 ms |

模块化在 6 组配对中有 5 组首音频更快，1 组更慢。14 次测试全部通过；带停顿输入每次只产生一个识别结果，回答正确。两次停止口令均识别为 stop-speaking，并产生 semantic-floor-change 的 playback_stop 事件。

主要收益来自回答生成到首音频阶段。识别阶段基本持平；目前模块化 ASR 是整段上传，较短的本地结束等待并未换来明显更快的最终转写。双方仍约有 0.93 秒用于 JEV。以上为各指标独立中位数，不能机械相加还原端到端中位数。

## 解释与限制

如果目标是“更快开口”，模块化本轮略优；如果目标是“完整音频更快生成完”，Omni 本轮略优。回复措辞、音频长度、音色和模型不同，完整输出时长不能解释为相同波形的纯吞吐对照。

这是现有默认配置的系统对照，未强行统一 VAD 阈值，也不是模型裸性能对照。网络和机器负载会影响结果；两组发送调度的最大落后分别为 143.8/144.4 毫秒。只有两种算术问题和每后端一次打断，不足以证明日常复杂对话、连续打断、背景说话或长期会话稳定性。未测试真实麦克风、回声消除和扬声器，首音频收到、完整音频收到及停止事件均不代表人耳实际听到/播完/停止。

第一轮出现一次模块化共享 JEV `SocketTimeoutError`，与媒体后端无关；路由已增加一次受总时限约束的快速传输重试，并在复用连接异常时使用新连接。

## 第二轮复测

修复后使用同一组输入 WAV、交错后端顺序和三轮重复，结果如下：

| 指标 | Omni | 模块化 |
| --- | ---: | ---: |
| 正确回答且收到音频 | 6/6 | 6/6 |
| 输入结束到识别文本，中位数 | 1212.4 ms | 1266.1 ms |
| 输入结束到首音频，中位数 | 3170.9 ms | **2915.5 ms** |
| 输入结束到完整输出，中位数 | 3291.1 ms | **3225.3 ms** |
| 停止口令结束到 playback_stop，单次 | 2339.2 ms | 2281.2 ms |

第二轮的 14 次测试全部通过，包含带 500 ms 停顿的连续输入和长回答期间的停止口令。该结果支持切换默认后端，但仍不代表真实麦克风、回声消除、扬声器播放或复杂长期对话已经充分验证。

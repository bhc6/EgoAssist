## 1. 主张要先收窄

推荐问题：**持续更新的长期交互中，如何在有限读取预算下选齐有效证据，并以较低维护成本保持这些证据可用？**

“三链路、记忆分层、加 embedding、加图、时间戳、JEV 路由、来源 ID”都不足以单独构成创新：论文已有相关方法，我们也已有不少实现。首篇聚焦两个可拆分机制：

- **查询驱动的事件证据组选择与原文展开。**复用 LongEvents、SourceIndex、Timeline 和向量缓存，研究如何让历史事件帮助召回和最终选择。
- **版本有效性约束下的局部修复。**复用 supersedes、来源依赖、manifest/stale，研究哪些受影响视图需要重建、何时重建、重建后是否真正恢复正确回答。

两个机制若不能形成共同的收益链，不强行绑定：只保留有证据的贡献。程序性学习、声纹识别、人物追踪、实时语音策略不加入主实验变量。助老可作为演示应用，论文的任务域是通用生活与工作记忆。

## 3. 假设、对照与可证伪判据

以下是**研究目标，不是结果或保证**。`pp` 指百分点。

| 假设 | 必须比较 | 主要预期与判据 | 若不成立 |
| --- | --- | --- | --- |
| H1：事件证据组能在固定预算下提高可回答性 | 相同 reader、来源、embedding 与预算下，对最佳开发基线 | 主测试效果目标 +5 pp；差值校正后的 95% CI 下界 >0；支持证据指标同步改善 | 查候选/选择/阅读分段，不只换更大模型；仅工程接通不宣称算法创新 |
| H2：局部修复能保持更新正确性并降低维护成本 | 同表示全量重建 + 原文 RRF + Graphiti + 仅失效隐藏 | 比全量重建维护成本低 ≥30%；修订探针准确率差值下界 >−2 pp；不能靠拒答或陈旧结果换成本 | 若 CI 不足则“尚不能证明非劣”；若错误扩大，缩窄修复依赖范围 |
| H3：方法提供实际效果—成本优势 | 在相同流量和更新负载下的强低成本基线 | 总成本低 ≥20% 且质量非劣界 >−2 pp，或同总成本质量有显著提升；不能只比昂贵重建 | 若仅降在线延迟，论文只声称延迟/维护调度收益 |

H1 在 LongMemEval-S 的主指标为官方 QA correctness；EgoLife 主指标为答案正确且有有效充分证据的联合通过率，另完整报告官方四选一准确率。两者分别统计，不能混成一个分数。H2 是预先定义的非劣检验，“没有显著差异”不能当非劣成功。

`+5 pp / −2 pp / 30% / 20%` 是本草案建议的最小有意义差异或工程目标，冻结前结合开发集方差、实际成本和样本量确认；不能在看到测试结果后调低门槛。

## 4. 待实现机制的最小规格

### 4.1 事件证据索引和预算选择

1. 以原始 source 为事实依据，事件是派生索引：记录 event/revision、人物、时间区间、阶段、source IDs、来源版本、覆盖缺口。保留现有字段，新增查询入口。
2. 问题同时提名原文/卡片/事件候选；复用词法、已有 dense/RRF。时间和人物不确定时保留候选及置信，不用错误的硬过滤删掉全部支持。
3. 命中事件后提名其原始来源及必要相邻片段；跨事件连接必须回到来源，不能把生成摘要视为第二个独立证据。
4. 最终在 token 预算内选择证据组，兼顾问题中的人物、关系、时间及所需步骤，扣除重复和失效风险。先实现透明启发式，比较普通分数排序、相邻窗口和 MMR，之后才考虑学习选择器。
5. 对精确数字、否定、人物归属和事件次序保留原文。回答携带 source IDs 与版本，记录无法确定的范围。

可研究的目标为 `query_slot_coverage(S) + bridge_value(S) − redundancy(S) − invalidity_risk(S)`，约束 `serialized_tokens(S) ≤ B`。slot 和 bridge 必须从问题及已可见候选估计，不能访问 gold evidence、正确选项或未来数据。目标含组间互补项，不预先声称具有次模性或最优性；选择策略本身必须消融。

主要接口落点：`egoassist/memory/source_index.py`、`egoassist/memory/long_events.py`、`egoassist/memory/timeline.py`、`egoassist/core/source_events.py`。研究 adapter 可读取派生事件索引，但不伪造原始 source。当前近期事件快照不能当作完整历史检索。

### 4.2 版本约束与局部重建

区分四类输入：状态发生变化、纠正原记录、迟到的历史信息、删除来源。每类都记录有效时间和系统获知时间；同一句“后来改了”不自动等价“之前说错了”。

研究依赖图包括 `source revision → card/event revision → summary/index entry`。处理变更时先标记受影响的派生物，再局部重建；未验证的新版本不覆盖已验证版本。查询需选择在问题时间与获知截止点可见的版本，对受影响但尚未修好的证据进行有界修复或明确拒答。重建产生的新依赖需重新登记。

至少检查：修订竞争、乱序到达、重复重试、重启、失败重建、无关记忆误伤、旧值复活、历史保留。读取与更新并发时记录 snapshot/version fence，避免一份回答混用不兼容版本。**依赖失效本身是已有工程思想；科研贡献必须体现在完整性、成本及错误率对照。**

不得把纠错简单等同新值覆盖：真实状态变化允许回答旧时点的旧状态；原记录错误可使过去时点的事实答案改变，但要保留“当时系统知道什么”的审计区别。删除来源后不能以“历史保留”名义继续泄露被删内容。

## 5. 数据与划分：公开基准、真实流、受控变化各司其职

### D0：已有开发与回归资料

保留 LoCoMo 304 个检索包、旧 EgoLife 30 题及所有失败案例。增加 60 个非测试校准题，覆盖单事实、多跳、时间、更新、拒答与事件计数，用于 adapter、judge、成本和方差校准。不能把重新表述旧问题当独立新题。

### D1：LongMemEval-S，计划 500 题

- 用官方 release、官方问题和类别，保留官方评测；登记仓库 commit、下载文件 SHA256、问题 ID。
- 冻结前审计是否已有运行/人工查看造成的暴露。目标是尚未用于本项目调参的 500 题；若有暴露，分开报告，不能仍称全部独立测试。
- 不从这 500 题挑“适合我们”的类别调参。开发用 D0 或独立生成/其他来源题；公开 benchmark 本身不保证基础模型从未训练见过。
- S/M 共享问题体系，M 只可作为长度压力扩展，不算第二份独立成功证据。
- 按原始支持会话、persona 与源历史家族登记相关性；同一支持来源的问题属于同一统计组。共享无关干扰文档不自动把全库并为一个组。

### D2：EgoLife，目标 80 开发题 + 400 测试题

- 先清点官方 QA、caption/ASR、人物、日期与媒体可用性；目标覆盖至少三个此前未用于本项目调参的参与者。具体 ID 和数量尚未冻结，不把旧 30 题填入新测试。
- 以参与者/连续录制段或日期分组；同一事件、近重复问题、上下文窗口及其改写保持在同组。开发参与者与测试参与者分开；若只有同人跨天资料，明确降级为同人时间泛化。
- 先运行 **memory-only**：所有方法收到相同的官方描述/转写、时间和说话人元数据，不额外给我们更好的感知。类别尽量覆盖人物、位置、事件顺序、计数与跨事件关系；不足时按实际分布报告，不生成伪官方 QA。
- 为 400 题补充最小充分证据集合，允许多个等价支持集合；两位标注者独立标 100% 测试证据，分歧仲裁。需区分“媒体有证据、给定 caption 无证据”和“给定文本确实足够”。官方 MCQ 仍全量评分，支持性在与输入匹配的标签下评分。
- 六位参与者即使产生数百题也不等于数百个独立人群样本。报告各人/日期效果和分组不确定性，不据此主张广泛人群泛化。
- 可选 **原始媒体轨**：另选 120 个预先冻结的片段任务，统一帧/音频预算及感知模型，3 个方法共 360 次回答；单独报告感知与记忆损失，禁止给某方法使用目标帧定位。

### D3：变化与修复挑战集，计划 100 条轨迹

开发 20、测试 80；每条 6 个读取探针，正式测试每配置 480 次回答。十类各 2 条开发 + 8 条测试，覆盖生活、工作协作、出行、学习场景。与公开数据互补，不能用自建合成集替代 D1/D2 的外部有效性。

| 变化家族 | 要暴露的失败 |
| --- | --- |
| 当前位置或状态改变 | 旧状态覆盖新状态 |
| 显式纠正此前记录 | 只改新卡，旧摘要仍被引用 |
| 迟到的历史信息 | 把获知时间当发生时间 |
| 多跳依赖的一端变化 | 一跳更新后，组合答案仍错 |
| 相似姓名/身份更正 | 修改到错误人物或跨人污染 |
| 否定、条件或偏好范围更正 | 抽掉限定词后过度泛化 |
| 重复来源、乱序及重试 | 已退休版本复活、重复计数 |
| 来源撤回/删除 | 派生结果继续暴露被删内容 |
| 局部观察缺口或事件拆分/合并纠正 | 缺证据被当零、重复事件被计两次 |
| 更新与后台整理/重启交错 | 读到混合版本或重启回退 |

六探针：变更前、变更后当前值、变更后历史时点、换问法/新会话、整理或重启后、未受影响的控制事实。每种变化预先写清预期值与来源关系；删除场景不能继续返回已删除事实。模板家族/人物/值/措辞按生成种子分组，不只是随机拆单条句子；测试使用新措辞模板，但不冒称未见过的变化类型。

变更事件与答案标签分离储存；更新器只看用户可见事件，不接触 gold 目标关系。明显歧义的更正允许请求澄清或拒改，另报澄清率及错误改写率，不能强迫写入后再算成功。

**三个具体测试例（均为计划中的合成材料，不是已经完成的实验）：**

- **状态变化和追溯纠错：**09:00 记录设备在 A，10:00 记录移到 B，10:30 用户纠正“09:00 实际在 C”。在 11:00 问“现在在哪”应答 B；问“09:15 实际在哪”应答 C；问“09:30 时系统记录它在哪”应答 A，并说明当时记录后来被纠正。只保留最新卡或无差别覆盖都会失败。
- **多跳工作约定：**记录“陈负责项目 X，X 的评审在周四”，后续更正“X 改由李负责，评审推迟到周五”。新会话问“李负责项目的评审何时举行”，必须组合正确版本的负责人关系和日程；同时询问未变更项目 Y，检测局部修复是否误伤。
- **观察范围与计数：**同一次喝水被连续三帧观察，之后有 20 分钟无采样。询问“记录到几次”应按事件去重；询问“这段时间一共喝了几次”不能把缺口当作无行为。再撤回一帧错误人物归属，检查事件参与者和计数是否被正确重建。

### D4：可选外部扩展，主结果稳定后再做

- MemoryAgentBench 的 FactConsolidation-SH/MH：固定官方 split、commit、chunk 协议；数量在清点 release 后登记，不编造已下载数量。用来检查 D3 是否只对自建模板有效。
- StreamMemBench：选 80 个新锚点、2 个系统；每锚点执行 T1、反馈后回答、同检查点 T2/no-commit 与 T2/commit，共 640 次回答。报告 Fidelity/IEU/FI/FUR；两分支共享此前轨迹，不能各自生成不同反馈。其 EgoLife 来源与 D2 重叠时不当独立数据集。
- MemoryArena / ReasoningBank 风格任务学习另立研究，不在首篇同时追求全量行动能力。

## 6. 基线与公平比较

### 主比较的八个配置

| ID | 配置 | 为什么不可缺 |
| --- | --- | --- |
| R0 | 当前生产记忆策略的离线 adapter；冻结 `2baed4c` | 证明优于我们已经做过的工作 |
| R1 | 原文 BM25，统一时间/主体范围 | 低维护成本基线 |
| R2 | 原文 dense + BM25/RRF，复用已实验实现 | 防止把 embedding 收益归因于新机制 |
| R3 | 原文值 + fact-augmented key + time-aware query；开发集在简单排序/MMR 中选优 | LongMemEval 启示下的强简单基线；标注为 adapted recipe |
| R4 | 官方 Graphiti 的固定 commit，原生构建/检索，固定 reader adapter | 与时间知识图竞争；不得标成完整商业 Zep 论文复现 |
| R5 | 官方 LightMem 固定 commit，记录压缩/主题/更新配置，固定 reader | 与效率方法竞争，建库成本不能忽略 |
| M | 两个待验证机制组合，保留来源与版本 | 候选方法 |
| F | 合法上下文内完整原始历史 + 同 reader | LongMemEval-S 的长上下文参照 |

D1 运行八组，D2 memory-only 运行 R0–R5/M 七组：长期视频描述可能超出 reader 上限，不把截断历史冒称 full-context。D1 若也超限，记录不能运行的数量和原因；不默默截断或排除失败，另报共同可行子集诊断。

**两种比较不要混淆：**主表固定输入、reader、预算，隔离记忆组件；论文原生模型/提示词的 native-recipe 验证单独附录。先给 R4/R5 各 60 个校准题核验原生配置（可选 120 次回答），确认 adapter 没有破坏格式，再固定调整说明。不能把自行重写的类命名为“官方复现”。官方仓库参考：Graphiti `getzep/graphiti`、LightMem `zjunlp/LightMem`、LongMemEval `xiaowu0162/LongMemEval`；具体 SHA 在运行前填入登记。

若 R4 或 R5 无法在同输入轨道运行，报告未完成和原因；不能拿一个空实现跑低分，也不能声称击败外部方法。EgoLife 输入适配需公开转换规则；LightMem 本身针对对话的适用限制单列。

### 固定项

- 同 reader 的完整 resolved model ID/版本、prompt hash、温度 0、最大输出、上下文上限、tokenizer、语言、时区；某 API 不支持 seed 时如实记录，不伪称确定性。
- 同感知输入和身份信息。人物 oracle 仅单列诊断；系统的自动身份错要计入系统轨。
- 证据预算主值 4096 tokens；敏感性 2048/8192。所有引用、元数据、摘要与原文计入证据预算；system/question/output 分开报告。
- 问题文本可进入检索；gold 证据/目标时间/正确选项只在评分侧；MCQ 的所有选项仅提供给统一 reader，不用于构建或选证据。
- 主实验固定或缓存共享 JEV/查询解析输出，使配置接收同一解析；按完整系统归因分摊其成本。另做端到端路由误差诊断，不把基于 gold 的时间解析当真实成绩。
- 硬授权/用户/删除边界所有配置一致。算法研究不得通过去掉这些边界涨点；时间语义过滤本身可以作为已声明的实验变量。
- 拒答策略及回答最大长度一致。MCQ 强制选择与允许拒答任务分开，不以拒答抬高分母内准确率。
- 更新顺序只依赖当时已知输入；未来摘要、全库未来 IDF/图统计、未来 persona 归并也可能泄漏，不能只过滤最终帧。
- 静态评测不把模型答案写回记忆；D3/D4 只按计划提交反馈，且各系统独立状态。

## 7. 具体实验矩阵及运行规模

| 实验 | 样本/配置 | 回答次数 | 主要问题 |
| --- | --- | ---: | --- |
| P0 校准 | 60 题 × 8 配置 | 480 | adapter 是否等价、成本/judge/错误分布 |
| E1 长对话 | D1 500 × 8 | 4,000 | 有限证据对比长上下文是否有效 |
| E2 生活事件 | D2 400 × 7 | 2,800 | 事件证据选择是否跨场景成立 |
| E3 修复 | D3 80 轨迹 × 6 探针 × 5 | 2,400 | 修复正确性、过期回答与维护成本 |
| A1 检索机制消融 | 预先固定的 D1/D2 各 150 题，共 300 × 3 | 900 | 事件表示、原文展开、组选择各自作用 |
| A2 修复机制消融 | D3 480 探针 × 2 | 960 | 读时版本验证和局部重建各自作用 |
| C1 预算曲线 | D1+D2 共 900 × 3 方法 × 额外 2 档预算 | 5,400 | 优势是否只发生在特定 token 档 |
| **计划核心总量** | P0 + E1–E3 + A1–A2 + C1 | **16,940** | 是最终回答次数，不是总 API 次数 |

主结果 E1–E3 为 9,200 次回答；阶段必须按门槛推进，不一开始运行全部。C1 的三方法为 M、R2、开发集预先选出的强外部/适配基线，选法冻结，不能看测试后换对手。

E3 五配置：有效原文 RRF、官方 Graphiti、现有只失效/隐藏策略、与 M 同表示的全量重建、M。全量重建是修复正确性与维护成本参照，**不是唯一对手**。只失效也允许真实拒答，但按答题覆盖和质量计入损失。

A1 三个分别替换 M 的组件：事件提名换为固定相邻窗口；去原文展开只读摘要；组选择换为同候选简单排序/MMR。A2 分别去掉读时版本检查、去掉局部重建但保留失效。共同保留基本隐私/授权边界。需要报告实际 token 和候选量；“只读摘要”不为凑预算填无关文字。

另在开发集先运行完整 2×2 因子实验（事件机制开/关 × 修复机制开/关），检查两者是否有交互；若独立有效但没有共同问题，论文分开解释，不把组合额外增益编出来。

可选扩展回答数：媒体轨 360；StreamMemBench 640；预先固定 100 题 × 3 方法 × 2 个额外 seed 为 600；R4/R5 原生校准 120。全部加入则 **18,660** 次；不含 FactConsolidation、2×2 开发筛选、抽取/索引/裁判/重试等调用，均需另行计账。主运行一次 seed，额外 seed 仅衡量随机稳定性，不算新增独立问题。

## 8. 指标定义：不能把不同含义的“涨点”混在一起

| 层级 | 指标与分母 | 用途 |
| --- | --- | --- |
| 候选 | 标准引用 Recall；完整支持集合命中率 | 判断证据是否进池 |
| 选择 | 最终有效证据 Recall；至少一个最小充分支持集合被完整覆盖的题占比 | 判断是否丢桥接或选了无效版本 |
| 回答 | 官方 correctness / MCQ accuracy；答案正确且有效证据充分的联合通过率 | 区分猜中、答对但乱引用和真实支持 |
| 选择性回答 | 全体覆盖率、回答部分风险、可回答题拒答率、不可回答题误答率 | 防止全拒答提升表面可靠性 |
| 更新 | 当前/历史探针准确率、stale-answer rate、错误修改率、无关控制退化、复活率 | 判断更新是否真正可用且不误伤 |
| 维护 | 受影响视图修复 precision/recall、重算 token/调用/时间、更新到可正确读取的时延 | 定位局部修复机制 |
| 成本与延迟 | 建库、增量写入、修复、检索、回答、重试、后台各项；P50/P95 | 判断总开销与在线体验 |

多种正确证据集合存在时，满足任一完整集合即可；单一旧 gold 不覆盖等价支持时进行盲审，不自动判错。无证据标签的问题不参与引用 Recall 分母，但保留在答案/拒答评分。事件计数需给可观测范围；从少量帧猜当天次数不算支持正确。

`stale-answer rate` 的分母是全部可评分更新后探针，而不是只挑给答案的探针；同时报告回答部分的 stale 风险与覆盖率，避免拒答掩盖问题。依赖图精度/召回只在 D3 有完整人工依赖标签的子集中计算，不能用系统自己的图给自己打分。

Judge 复用官方评分并增加统一证据审查；模型/提示词固定，输出正确性、来源支持、时间/人物错误的分项。人工盲审至少 200 个按方法/题型分层抽样的回答，另审所有方法间争议；争议样本不可当随机样本估计全局准确率。抽样误差需按原分布加权，双人一致率与仲裁记录公布。不得用 answer 模型的 `supported=true` 自报作为事实真值。

## 9. 成本设计：怎样证明降本

总成本按一次完整部署负载计：

`C_total(N,Q,U) = C_ingest(N) + C_embed(N) + C_update(U) + C_repair(U) + Σ[C_route + C_retrieve + C_read + C_retry] + C_background + C_storage/compute`。

运行每个调用记录 provider、resolved model、输入/输出/缓存 token、调用原因、开始结束时间、错误和重试、单价快照、request ID；不把 API key 写入日志。费用取运行当日可核验单价或真实账单，当前文档不臆测未来价格。研究 judge/标注成本与部署成本分开，但都报告。

- 同时给冷启动、热缓存和真实增量三套数字；使用已有 embedding 缓存不等于首次建库免费。
- 负载：每 1,000 次来源追加包含 0 / 10 / 100 次更新，读取次数 Q 为 1 / 10 / 100 / 1,000。分别报告 append 成本和 correction 成本，不能重复相加同一动作。
- 全量重建与局部修复采用相同完成时限：公平比较同一批次/同新鲜度，不能让局部方法无限等待而让基线每条全重建。
- 若 M 多花建库 ΔB、每次读省 ΔR，则仅在 ΔR>0 时可讨论 `Q*=(ΔB+U·ΔU)/ΔR`；同时画更新频率对回本点的影响，出现负分母意味着不靠查询次数回本。
- 回答输入 token 降低不能替代总费用降低；同一次回答的多个模型/工具/重试必须全部计入。CPU/GPU/存储不能只写零，至少报告资源与时间。

**预算粗算示例，非价格承诺：**核心主实验 9,200 次回答中，500 次 full-context 按平均 115k 输入估计，其余 8,700 次按 6k 输入，约 109.7M reader 输入 token；按每次 300 输出为 2.76M 输出。若每题再评审 2k/150 tokens，则新增 18.4M/1.38M。合计约 **128.1M 输入 + 4.14M 输出**，尚不含建库、更新、embedding、其他实验和重试；分模型乘实际单价，不把不同模型 token 按一个价格计费。full-context 长度按实测替换，不能把所有组都假设成 4k。

建议先完成 P0 取得真实账本，再给每阶段填写美元上限和预留 20% 的异常空间；登记未填预算/模型/数据 SHA 前不能将计划标记为 ready。**这只是待执行计划，本轮没有发起这批调用。**

## 10. 统计、泄漏与可复现性

1. 主比较预先指定 M 对开发集选定的最强基线，不在测试集挑最弱对手。E1/E2 两个主端点做 Holm 校正；消融多比较另建 family，明确哪些是探索分析。
2. 使用成对、按源历史家族/轨迹分组的 bootstrap（预设 10,000 次）；同题 seeds 在组内汇总。独立二元配对可附 McNemar，不将其直接套到同人同日高度相关问题。
3. D2 至少逐参与者、逐日期报告。参与者数量太少时 bootstrap 区间并不保证人群有效性，使用留一参与者敏感性分析，并限制结论。400 题不能掩盖只有几个人。
4. 粗略功效：若 discordant 比例约 0.2，检测 5 pp 差异、双侧 α=0.05、80% power，正态近似需约 `((1.96+0.84)^2×0.2)/(0.05^2)≈628` 个独立配对；多重比较、聚类还会增加需求。这不是本方案保证功效的计算，500/400 题可能只能稳定检测更大差异。
5. P0 用于估计方差与聚类效应，在测试解封前决定可检测差异。样本不够时报告宽区间/探索性结果；不把 p>0.05 写成等效。若后续追加样本，先制定新协议或序贯设计，不能看完结果后一直加到显著。
6. 所有测试 ID、来源窗口、变更轨迹、模型/提示词、代码、基线 SHA、预算、评分和统计脚本在运行前生成冻结 manifest。登记修改原因及新版本；“预注册草案”不等于已公开预注册。
7. API 失败、上下文超限、解析失败与拒答保留。固定所有方法相同的重试上限；同时报含失败的实际效用和预定义共同可执行子集，不能按成功日志重新筛样本。
8. API 模型可能漂移：记录 resolved ID、日期与 provider fingerprint（若提供），以交替配置顺序减少时间漂移；不支持 pinning 时承认限制。不从调参过程挑最佳单次 seed。

## 12. 如何形成可信的论文叙事

候选标题：**Evidence-Complete Memory under Continuous Updates and Bounded Budgets**（持续更新与有限预算下的完整证据记忆）。这是工作标题，不是已验证的能力描述。

叙事按证据展开：

1. **问题：**记忆系统即使召回相关片段，仍可能遗漏组合证据；信息修订后，派生事件/摘要与来源不一致又会让旧答案复活。
2. **诊断：**给出候选、最终证据和回答的损失漏斗；旧开发数据只用于提出问题，正式测试重新测量。
3. **方法：**定义可追溯、可版本校验的证据组，在预算内联合选择、展开，并针对变更修复受影响部分。
4. **证据：**在长对话、真实持续观察和受控变更上，比较强原文方法、图更新方法及轻量记忆方法；展示收益来自哪一步及何时回本。
5. **边界：**事件合并错误、身份/时间歧义、不可观测行为、极低查询复用和模型漂移可能让方法失效，给出真实失败而非只展示成功故事。

建议主图：问题与数据流；证据损失漏斗；质量—总成本 Pareto 图；更新频率—过期答案/维护成本；组件消融；一组成功与失败的证据/版本轨迹。主表分 D1/D2/D3，不能把不同评分合并成总冠军分数。

**结果决定故事：**

- 质量和总成本都改善：可主张有限预算下的记忆效率改进。
- 质量提高、总成本也提高：主张预算内更强证据组织，诚实报告成本，不宣传降本。
- 同质量降低维护成本：主张增量一致性和高更新负载效率，不宣称推理变强。
- 只在自建更新集有效：作为局部机制/挑战集结果，需要外部验证，不能推广通用记忆。
- 只优于生产但不优于强 RRF/Graphiti：是有用工程集成，算法新颖性证据不足。
- 无稳定提升：发布负面发现或继续开发，不能靠重新挑题、换指标、过滤失败完成“涨点故事”。

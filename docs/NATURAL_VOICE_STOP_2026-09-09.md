# 自然语音停止与延迟审查

后续[扩展打断研究](INTERRUPTION_RESEARCH_2026-09-09.md)发现口误、第三方话语及取消对象问题，并以真实模型复现。本文记录的成功样例仅覆盖相应场景，不代表自然交互完整可用。

停止声音与取消问题分开。设备在供应商 VAD 检测到用户开口时收到 `playback_stop`，不等待转写或语义模型。之后只调用已有语义路由，判断是安静、撤销回答、改问新问题，还是引述/否定；不新增串行分类调用，不添加停止关键词或正则。

## Review 修复

| 问题 | 修复 |
| --- | --- |
| 停止正则命中后丢弃先前片段 | 删除 `_STOP_RE` 和语音入口命中分支，全部片段送入同一语义路由 |
| 云端生成已结束但设备仍播放缓存 | 无活动模型请求时仍发停播通知；浏览器清空 PCM 队列、屏蔽已停止响应 ID |
| 短句/保护策略延迟用户要求安静 | 设备播放立即停止，供应商内部生成按原策略收尾；语义停止后取消生成。保护策略不能强迫用户继续听 |
| 纯停止仍经过记忆检索与工作项创建 | 分类后直接完成语音控制，记录真实路由与停止事件，不查记忆、不写记忆、不新建回答义务、不说“好的” |
| 先安静再取消会指向上一条停止命令 | 给路由提供 `previousAnswer` 与 `previousTurn`；只允许引用服务端提供的目标 ID |
| 模型只返回取消而未返回停止标签 | 纯取消且无其他意图时在协议层统一为静默控制；保留复合请求里的新问题 |
| LiveKit 仍有播放队列 | 停播事件清理服务端音频队列，阻止该响应后续音频；前端静音，到新响应才恢复。LiveKit 真服务器和实物耳机尚未测量 |

提示词在 `egoassist/prompts/answer_completion.json`；状态转换与 ID 校验属于协议约束，不依据用户说出的关键词做分支。普通新话题只抢占语音，上一轮的自动文字补答策略保留。

## 真实测试

`outputs/natural-voice-stop-real-2/acceptance.json`：6 种真实语义判断通过，包括直接要求安静、委婉表达、撤销回答、引述、否定及取消后新问题。三段输入由真实 `qwen3-tts-flash` 生成 WAV，再按实时速度发送 16 kHz PCM，经实际 Qwen 实时 ASR 和服务器完整处理。保存 WAV、识别原文、供应商请求 ID、提示词和状态事件。

| 口头内容 | 发送音频至停播通知 | 发送音频至语义控制生效 | 路由耗时 |
| --- | --- | --- | --- |
| 闭嘴 | 299.280 ms | 2238.902 ms | 426.8 ms |
| 让我安静一会儿，先别出声 | 287.871 ms | 3846.696 ms | 476.3 ms |
| 这个答案我不需要了，不用继续回答 | 289.200 ms | 5727.180 ms | 1258.7 ms |

语义控制生效耗时包含说完整句话、供应商端点检测、ASR、250 ms 片段合并等待及路由；最后一列仅为路由耗时。不应把整句识别耗时称为停播延迟。该次产物字段名 `speechOnsetToPlaybackStopMs` 的实际起点是第一块音频发送，脚本已改名 `audioSendToPlaybackStopMs`；没有测量真实声学起点。

`outputs/natural-voice-stop-browser-1/acceptance.json`：真实 Edge 接收并播放 Qwen 音频，送入委婉停止语音，313.1 ms 收到 VAD 停播事件时播放源已为零；语义控制 4107 ms 完成。随后新问题可正常播放，1440/390 像素无横向溢出，页面错误为零。截图保存在同目录。

`outputs/natural-stop-attribution-real-1/acceptance.json`：七种真实归属、打断、更正、取消和重连场景均通过。早期 `natural-voice-stop-real-1` 因模型仅返回取消标签而失败，修复后的真实复测保留独立目录，没有覆盖失败日志。

完整自动化测试通过：396 项、零失败、零错误、零跳过，耗时 64.309 秒；结果保存在 `outputs/natural-stop-full-final.xml`。该套自动化测试包含隔离测试，与上述真实模型验收分别记录。

## 限制

VAD 对任何用户开口先让出声音，不会在声音开始时就知道其语义。噪声、回声、多人交流可能误触发，眼镜端仍需基于实际麦克风、回声消除和佩戴场景验收。此轮真实音频输入为合成语音，不是人工录音或实物眼镜。云端网络中断时仍不能靠服务器 VAD 实现本地即时停播；硬件确定后应接入设备端已有 VAD 与播放取消接口。

短句和长句的停播耗时相近，是因为停播不等待完整识别。取消后台回答仍依赖完整识别与模型理解，不能承诺任意口误、方言或含糊指代都正确。此前完整验收中的时间锚点、降级时间索引和月报截断问题不在此轮修复范围内。

复现：`.venv\Scripts\python.exe scripts/verify_real_voice_stop.py --output <新目录>`；浏览器使用 `scripts/verify_real_voice_stop_browser.py`。统一真实验收入口已加入这两组，总计 19 组。

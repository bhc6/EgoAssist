## 已定位并修复

| 风险 | 原行为与影响 | 当前修改 |
| --- | --- | --- |
| 高：连续输入阻塞 | WebSocket 等待整轮语义处理后才读下一条控制，打断也排在慢请求之后 | 持久化后入队，读循环继续；分类并行、案例状态转换串行 |
| 高：旧输出错位 | 浏览器没有问题 ID 过滤，打断后字幕缓存可能延续 | 传递问题与响应 ID，发送前检查连接及输出代次，浏览器重置并隔离字幕；无问题来源的普通回答拒绝输出 |
| 高：假完成 | `response.done` 内部可以实际为 failed/cancelled/incomplete；字幕结束被当作回答结束 | 解释嵌套终态，前端等待响应终态；另记中断、异常与断线结果 |
| 高：旧定时器打断新回答 | 保护播报到期只检查当时是否存在保护响应，没有绑定原响应 | 绑定响应 ID 和连接代次，取消前在锁内再次核对；尚未创建的保护响应可立即取消 |
| 高：重试重复执行 | 明确文本请求缺少客户端幂等 ID | 同案例相同 ID 与内容去重，冲突内容拒绝；原文保留 |
| 高：回执前刷新 | 发送与服务端持久化回执之间没有可恢复请求 | 标签页暂存按账户和案例隔离，刷新后原 ID 重发，收到回执再移除 |
| 中：旧问题无交代 | 内部处理 completed 与回答 completed 混为一谈 | 独立 delivery 记录；历史列出未完成问题，可显式重新提问 |
| 中：报告恢复停止 | 连续重启超过两次就失败，超容量恢复依赖刷新 | 不按重启次数放弃；任务结束自动补位，取消和失败不自动重试 |
| 中：报告状态隐藏 | API 只返回最近 12 项、UI 只显示 6 项，可能藏住待办 | 保留所有待办，终态仍限最近窗口；空闲时也轮询发现新增任务 |
| 中：假进度 | 等待模型与准备证据混同，伪心跳不能说明运行状态 | 真实阶段、执行次数、请求上限、记录覆盖与等待时间；断线披露旧状态 |
| 中：安装包缺资源 | PDF.js 的 `.mjs` 文件没有纳入 wheel | 补齐 package-data，构建后检查资源 |
| 中：测试误归属 | 真实测试接受“后续任意一个完成事件”，可能匹配旧响应 | 真实辅助函数和延迟验收按问题 ID、响应 ID 精确匹配 |
| 文档失真 | 旧 README/记忆文档混合预期架构、离线延迟和当前实时实现 | 重写当前文档，历史实验单独导航 |

## 仍需完成

1. 运行当前版本的全套真实验收，分析每次 `response.dispatched/created/finished`、问题 ID、响应 ID 与实际音频；任何失败均保留。当前真实审批故障解除前不能宣告交付成功。
2. 真实麦克风 ASR、口误、回声、眼镜音频输出、无线断流与实物动作尚未验收。文字更正只能验证编排；模型响应完成不等于用户完整听到。
3. 普通后续输入会打断旧前台播报。旧问题保存并显示中断，需用户明确继续；不会自动把所有历史问题再播一遍。已经产生的外部副作用不因换话题撤销。
4. 回执前文本使用标签页 `sessionStorage` 暂存；关闭标签页或清除站点数据仍可能丢失尚未送达的输入。该暂存按账户和案例隔离，并在删除账户时清除；不是跨设备持久消息系统。
5. 供应商自动恢复、工具调用、后台结果和多意图必须继续按来源核对。ID 约束能防传输错位，不能保证模型没有误解问题；同一问题的多个子任务状态在详细账本中审计。
6. 实时入口仍较大；单写租约和本地日志不支持多机执行。报告预算会遗漏超量记录，主动建议依赖在线控制台触发。
7. 原 8780 服务尚未切到本轮代码。新代码单独运行于 `http://127.0.0.1:8781/`，数据根目录为 `outputs/review-demo/`，供本地界面检查；HTTP 返回 200 不代表真实 Qwen 验收。替换原演示服务后仍需复验。

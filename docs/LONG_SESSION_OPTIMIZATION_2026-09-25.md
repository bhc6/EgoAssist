## 定位与修改

同一份 9193 行、约 61.8 MB 的历史中，简单计算及追问仍向 qwen-flash 发送约 2 万至 2.4 万输入 token。分解发现每条历史消息重复携带约 200 字符的相同时间解释规则；证据包逐条重复时间边界和索引审计字段。状态接口还会先深复制大量任务内容，再截取显示。

- **文字回答历史回放**：把时间解释规则放进系统上下文一次，每条历史消息只携带原始 `recordedAt` 标记和完整原文。角色、顺序、时间、否定和指代内容保持。仍先用原有 ContextHarness 预算选择消息，不缩小记忆预算，也不因标记变短而额外装入历史。Omni 持续语音会话保留原回放格式。
- **模型证据包**：统一时间解释边界，使用紧凑 JSON，移除内部 journal ID、哈希、索引状态和注解版本。保留 `sourceId`、`externalId`、`supersedes`、原文、摘录范围、人物、时间、媒体引用、不确定性和覆盖情况。特别保留 `externalId`，避免丢失导入记录的更正目标对应关系。原始持久化包、删除校验和后台恢复上下文保持完整。
- **三链路状态投影**：任务统计只投影状态所需字段，避免复制历史 prompt、场景和回答上下文；仍统计全部任务。状态面板的 intents/jobs/results 在复制前选择原本显示的最近 20 条。执行器及取消、恢复路径默认仍读取完整账本。
- **测量**：文字生成审计增加输入消息数、字符数；长会话脚本冻结源码及提示词哈希，输出真实 token 和首 token 指标，检测运行期间源码漂移。

相关实现：`memory/grounding.py`、`realtime/context_harness.py`、`realtime/omni.py`、`product/answer_service.py`、`runtime.py`、`realtime/work_ledger.py`、`application/state.py`、`realtime/modular.py`。

## 同历史真实复测

输入历史 SHA256：`3dead06d60341c9717174a114a6e6a2307819756b6f7424dd04ec922ce4ed520`。复制到隔离账号和会话，旧未完成动作全部取消，不执行历史任务。测试包含计算、使用上一答案继续计算、真实 ASR/语音回答及连续两条输入，共 5 个问题。

连续输入回执从基线约 558 ms 变为两次约 826 / 574 ms，没有证明改善。状态接口更快不代表每条输入回执都会等比例改善。语音每次重新合成，PCM 不完全相同，供应商及网络也存在波动，10.9% 只报告本轮观测值。

两次最终运行的 10/10 问题全部正确并完成，源码哈希无漂移。计时并发及剖析区别：中间开发运行与全量测试同时执行；最终两次没有同时运行全量测试。基线和最后一次最终运行对第一次状态读取启用了 cProfile，因此状态接口表格只统计每次后续两次无剖析读取。启动计时均含 cProfile，不作为正常启动延迟结论。

同样的状态剖析中，函数调用从约 153 万降至 67 万，累计剖析时间约 0.862→0.439 秒；三链路任务内容深复制已消除，但账本展示投影和其他历史读取仍有优化空间。

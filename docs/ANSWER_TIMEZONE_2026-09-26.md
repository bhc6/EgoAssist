# 回答中的 UTC 时间误读

用户询问“我今天喝了几次水”，回答把原始采样时间 `2026-09-26T06:19:50.369425+00:00` 直接说成当地 06:19:50。该会话回答时钟是 `Asia/Shanghai`，正确本地时间为 **2026-09-26 14:19:50**；后一帧为 **14:19:55**。

原始存储时间没有错。问题在于回答证据中同时存在 UTC 采样字段、JSON 字符串形式的观察正文，以及本地回答时钟，模型没有一致处理这些格式。

## 修改

新增只用于模型输入的时间投影：按会话 IANA 时区转换具有明确偏移的结构化时间字段，包括来源 `text` 字段中嵌套的 JSON 观察记录。前台语音回答、当前回合上下文和后台补答使用该投影。保留原始日志、来源 ID、来源时区元数据、UTC 权威时钟、未知时区时间及自然语言原文；不会用正则替换用户原话中的小时。

提示模型直接使用已转换的偏移时间，不再重复加时差；区分采样/接收时间与未知的画面事件时间。没有明确时区时不猜北京时间。时区转换不补足遗漏的画面，也不能凭物品离开画面证明动作完成。

## 验证

86 项相关测试通过，涵盖来源证据、后台回答、实时 API、文本语音通道；新增测试包含原始 06:19→14:19、跨本地午夜、纽约冬夏令时、未知时区、重复投影不会再加 8 小时，以及原数据保持不变。

以原提问时保存的证据包进行两次真实 `qwen-flash` 回答，原问题和明确询问本地时间均给出 14:19，后者明确 `Asia/Shanghai / UTC+8`。未重新检索用户记录、未改写旧回答。证据：`outputs/timezone-fix-20260926/real-answer.json`、`tests.log`。

实测答案仍有过长解释及从采样推断整个动作起止等措辞问题；本次仅确认时区修复，不宣称全天饮水计数或事件边界推理已完全正确。

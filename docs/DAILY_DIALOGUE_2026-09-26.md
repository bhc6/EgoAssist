# 日常对话：JEV 语义交接、连续输入与 EgoLife 迭代

日期：2026-09-26，Asia/Shanghai。

## 问题与修复

此前有四个条件叠加，使连续讲话经常听不到回答：设备 VAD 检测到声音就停播；服务端每段转写都增加输出代际、暂停播放并中断旧回答；发音只允许“最新收到的输入”；前端也丢弃非最新输入对应的音频。附和、背景人声、旁人交谈因而都可能打断原来的问题。另一个分支在 ASR 尚未结束时直接放弃语音，转为后台文字，没有等待间隙后补播。

现在收到输入只负责保存原文、建立来源和分类，不自动获得发言权。JEV 在原有同一次有限判断中选择交互动作；无需为附和再调用自由文本模型。观察与记忆的来源、处理顺序和写入校验保留。

| 语义 | 行为 | 是否生成新回答 |
| --- | --- | --- |
| 普通问题、问候、纠正、换题 | 取得新的发言权，停止旧声音，优先回答当前问题 | 是，默认简短语音及文字 |
| 附和、表示在听、鼓励继续 | `keep`；当前生成、已缓存音频和待播回答都保留 | 否 |
| 旁人交谈、无法确认是否对助手说 | 不切换发言权，不因背景输入停播 | 否 |
| “等等，我还没说完” | `wait`；暂时让出声音，不建立永久静默 | 否；下个完整问题恢复正常判断 |
| 明确停止、安静一会 | 停止设备播放，保留工作；按明确指令设置静默权限 | 否 |
| 要求继续原答案 | `resume`；优先按设备报告位置回放缓存，否则继续原问题 | 延续旧答案 |
| 明确取消某答案 | 只取消指定答案，保留其他工作 | 无新问题时不回应 |

“首先回应”指完整、指向助手的问题不能被后续附和吞掉，也不为了显示活跃而机械追加“好的”。用户还在形成问题时等待；只是在听时让原回答讲完。声纹未知不能直接等同于“他人”，也不能作为执行授权。

## 工程机制

1. `latest_input_sequence` 只表示接收顺序，新增 `speech_floor_sequence` 表示经语义确认的发言归属。`output_generation` 仅在有效的新发言决策时递增。慢返回的旧决策不能夺回较新的发言权，后到的附和不能使原问题失效。
2. 分类完成后先在互斥区选择发言归属，再进入按序的视觉、记忆和工具处理。明确停播不等待慢视觉。普通问题仍在其必需证据准备后作答，未增加无依据的提前答案。
3. 新发言先停止设备缓存，再更新权限并发送 `speech_floor`。浏览器按服务端输出代际过滤旧音频，不再按最新收到转写的 turn ID 过滤。附和不清空字幕、不新建答案、不重播已经播放的片段。重连重置客户端代际，服务端继续校验连接归属。
4. 尚有语音或更晚的未决分类时，已准备的回答有独立等待任务，最多等 8 秒，每 40 ms 检查，不阻塞 FIFO。附和/旁人分类结束后恢复发音；新问题或停止使旧等待失效。超时保留可审计的文字补答与状态，不无限等待。已被 provider 队列接纳的回答不误判为拒绝。
5. 已结束但回调丢失的 ASR 片段在 30 秒后记录 `stopped-asr-deadline` 并释放阻塞；正在说话的区间不因超时被清除。此恢复不是转写成功，也不虚构丢失内容。
6. 路由增加 `inputChannel` 与最近四条已记录 `recentInteractions`，帮助判断分段语音的说话对象。该上下文是带来源的模型推断，不是不可改变的身份标签。用户明确向助手提出新问题可立即切回。

关键代码：`interaction_controller.py`、`turn_coordinator.py`、`interaction.py`、`decisions_router.py`、`omni.py`、`application/realtime_connection.py`、`console/app.js`、`console/local_vad.js`。提示配置为 `decisions-router-v10` 及 `prompts/interaction.json`。

## 真实实验与失败迭代

所有产物在 `outputs/semantic-floor-20260926/`，默认不提交 Git；脚本入库，可重新运行。以下均为开发验证，不是独立盲测准确率。

- `regression-final.log`：899 项全量回归通过，4 个现有依赖警告。覆盖接收去重、FIFO、记忆、权限、后台工作、隔离、说话对象、延迟决策及输出代际。新增的语义发言测试使用假 provider，明确不当作模型质量证据。
- `jev-controls/report.json` 与最终 v10 的 `jev-controls-final/report.json`：两轮各 9/9 组真实 JEV 旧控制探针通过，涵盖指定答案取消、无法匹配目标、引用取消、语音/文字续答、静默与退出 Skill。
- `semantics-v1/report.json`：16/16 人工编写中英文探针通过。三个 EgoLife 文件各取前 18 秒，经真实 ASR 再分类；54 秒录音，分别报告无附加框定及实验者明确“录制人类会议”的条件。
- `browser-v1/acceptance.json`：**失败，保留结果**。真实 Edge、Silero、ASR、JEV、回答与 TTS 已通过附和不停播，但 EgoLife `11100000` 前 12 秒被实时切成两段后，第二句“传过去，戳一下。哎，能看到对吗？”误判为向助手提问，抢占当前回答。不能用整段转写测试通过掩盖这个失败。
- 修正为 v10：补充最近已判断的说话对象、输入渠道，并要求结合前文的群体物理活动判断整句话，不因末尾问号切换对象。没有按该句建立关键词规则。
- `semantics-v2/report.json`：18/18 人工开发探针通过，均仅调用 JEV；新增失败短句及“旁人交谈后明确叫助手”的对照。JEV 中位耗时 373.9 ms。本轮三个 18 秒 EgoLife 片段的六次分类均无新播报；说话对象无标注，不计算 addressee 准确率。
- `browser-v2/acceptance.json`：真实 Edge 全链路 7/7 检查通过：首问题有音频；Silero/附和不清播放队列；EgoLife 两段交谈不停播；语音换题答 81；暂等后新问题答 15；相隔约 50 ms 的文字问题与附和保留问题音频；明确停止清空设备队列。VAD 回调前后播放节点数均为 14。桌面 1440 px、手机 390 px 无横向溢出、无页面错误。
- `real-controls/acceptance.json`：真实回答的文字续答、语音恢复、取消旧目标而保留新目标、静默重连四组通过。
- `cache-resume/acceptance.json`：真实 Edge/Silero/ASR 停止后按 135343 个采样的设备位置继续同一 response，未从头播放；新问题及静默刷新通过。2.48 秒的合成停止语音从发送开始到语义停播约 4.88 秒，其中转写后到停播约 539 ms。必须区分端点检测等待与 JEV 控制耗时，不能把这一结果称为瞬时打断。
- `post-prompt.log`：补充自然回答不朗读内部来源标签后，77 项相关回归通过。
- `production/acceptance.json`：本地 8770 服务平滑重启后的隔离账号复测，7/7 检查通过，真实 ASR/JEV/生成/TTS/浏览器播放；两段 EgoLife 均判为对其他人说，不新增回答。VAD 前后播放节点均为 12，手机/桌面无溢出、无页面错误。`release/restart.json` 记录退出旧实例、等待数据根目录锁释放、新实例健康检查 200。

浏览器 v2 单次会话从收到转写到首个音频包：首问题 1337 ms、语音换题 1541 ms、暂等后提问 1572 ms、快速问题加附和 1903 ms。语义交接约 391–638 ms。**不包含讲话时长和 VAD/ASR 端点时间**，也不代表物理扬声器首声延迟或统计意义上的性能改善。

正式服务同组首音频包耗时为 1308、1736、1568、1562 ms。没有以缩短端点静默阈值换取更高误切句率，本轮改进主要是消除错误停播和丢弃待播回答。

## 边界与下一步研究

- EgoLife 的 SRT 是活动描述，不是逐字转写或说话对象真值。保留源文件哈希、区间、ASR 请求证据和全部决策；不把合成控制语音称为真人现场交互。
- 当前主要在完整 ASR 片段后做语义交接，不是实时逐词理解。立即打断仍受端点与网络延迟影响；保留当前声音时，物理回声消除质量更重要，本轮未做物理麦克风/眼镜扬声器测试。
- 八秒等待上限后转文字，连续长讲话没有无限自动补播。`wait` 让出声音直到后续明确请求；不会擅自把用户沉默解释为重新允许讲话。
- 多人混合一句话、重叠发言、极短附和、隐含对象仍可能误判。需要另外建立带说话对象和时序标注的保留测试集，测误打断率、漏回应率、错误插话率、首声延迟分布及回声场景。
- 当前没有承诺“先讲完这个、再自动回答一个新问题”的通用双回答排程；普通新问题仍优先切换。明确后续任务沿用现有任务机制。
- 独立记忆科研可以继续，但不能把本轮有限开发验收称为真人对话机制已完全解决。

## 复现

```powershell
.venv/Scripts/python.exe -m pytest
.venv/Scripts/python.exe scripts/verify_daily_dialogue_semantics.py --output outputs/daily-semantics-new --egolife
.venv/Scripts/python.exe scripts/verify_daily_dialogue_browser.py --output outputs/daily-browser-new
.venv/Scripts/python.exe scripts/verify_real_interaction.py --output outputs/daily-controls-new
```

需要已配置的 JEV/Qwen 凭据、Edge、已有 EgoLife 文件；输出目录须为新目录。默认隔离数据根目录，不读写用户原会话。加 `--base-url http://127.0.0.1:8770` 可在当前服务注册隔离验收账号验证部署。

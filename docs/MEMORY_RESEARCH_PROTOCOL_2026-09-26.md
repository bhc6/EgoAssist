# 记忆机制科研协议（2026-09-26）

## 研究选择

记忆机制的主实验使用**文字输入**，固定路由、回答模型和提示词，只改变记忆机制本身。系统级语音验证使用**模块化链路**；Omni 只作为最后的真实语音对照，不作为记忆算法主实验的变量。

这样可以把记忆写入、事件组织、时间检索、证据选择、更新和遗忘的影响，与 ASR、VAD、JEV 延迟、TTS 和网络波动分开。首音频更快不等于记忆更好，不能用端到端语音延迟替代记忆指标。

## 固定条件

主实验固定以下条件：

- 输入为预先冻结的文字转写，不测麦克风、端点检测或 ASR。
- JEV (`typesafe/jev-1.13`) 负责有限路由与证据范围判断。
- 需要自由文本解析时固定同一 Qwen 模型、提示词和输出协议。
- 回答模型、温度、最大输出、时间锚点、用户/案例范围和硬安全约束保持不变。
- 每个实验只改变一个记忆变量，并保存代码、提示词、数据和运行配置哈希。

## 实验阶段

1. **主实验：受控记忆检索**

   使用 `scripts/run_controlled_retrieval.py` 的 A-E 方案，对比 Timeline、词法 BM25、字符 BM25、语义检索、多粒度证据和选择性拒答。报告 Recall@1/@5、MRR、nDCG、证据支持度、引用有效率、覆盖率、拒答率、检索延迟、模型调用次数和成本。

2. **机制消融**

   逐项关闭或替换记忆能力：时间约束、身份/主体约束、来源范围、事件合并、旧值更新、负面证据、遗忘/过期和证据不足拒答。每次只改一项；错误类型按时间错配、主体错配、来源越界、旧值覆盖和无证据回答分类。

3. **系统验证：模块化语音链路**

   使用固定语音输入或 EgoLife 回放，设置 `EGOASSIST_REALTIME_BACKEND=modular`，测输入结束到转写、JEV、首文字、首音频、完整回答、漏回应、误打断和停止响应。语音验证只回答“记忆机制接入后是否仍可用”，不把 ASR 或 TTS 误差归因于记忆算法。

4. **最终对照：Omni**

   在模块化验证通过后，用同一输入、同一问题顺序和同一验收标准运行 Omni。只报告语音链路差异；不能用 Omni 的整体结果证明记忆机制改进。

## 运行边界

主实验命令：

```powershell
.venv\Scripts\python.exe scripts/run_controlled_retrieval.py `
  --dataset data_real/egolife `
  --output artifacts/memory-research-<unique> `
  --seeds 0,1,2 --workers 4
```

模块化系统验证前设置：

```powershell
$env:EGOASSIST_REALTIME_BACKEND = "modular"
.venv\Scripts\python.exe scripts/compare_voice_backends.py `
  --output outputs/memory-system-modular-<unique> --repeats 3
```

验证完成后恢复当前生产配置，不把研究环境变量写入生产 `.env`。主实验不得把目标帧、gold source、答案选项或未来事件传入检索器；gold 只能在检索返回后用于评估。

## 当前证据边界

已有 EgoLife 题目和单参与者数据曾用于开发、回测和规则修正，属于已暴露探索数据。它们可以发现机制问题和比较消融方向，但不能支持独立测试、跨参与者泛化或“科研结论已证明”。正式结论需要新的参与者/视频、冻结的标注协议、人工证据审计和预注册的独立测试集。

## 通过条件

只有在所有硬约束回归通过、证据支持度不下降、时间/身份/来源边界不退化、延迟和成本可解释，并在独立测试集与人工审计中复现后，才考虑把某种记忆机制设为默认。当前生产默认不因本协议改变。

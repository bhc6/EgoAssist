# 论文机制与 EgoAssist 已有工作的逐项对照

核验日期：2026-09-27。源码基线：`2baed4c`；本轮只有研究文档变更。对照前一轮已读取的 [15 篇论文](MEMORY_PAPER_FINDINGS_2026-09-27.md)，重新核查当前源码、测试定义、历史报告及关键实验 JSON。本轮没有重新运行模型评测或测试套件，没有启用新检索器，也未修改提醒或工具策略。

## 1. 先纠正前面的判断

把“向量召回、事件单元、观察缺口、记忆纠正、反馈和任务进度”整体写成未来新增能力不准确。它们中不少已有实现或实验；需要区分 **默认产品能力、显式启用能力、研究实现、工程验证和效果验证**。

更准确的判断是：我们已经实现了来源持久化、记忆卡片、时间/主体约束、局部修订与派生失效、后台事件和日记、任务恢复，并做过词法/向量/融合和原文检索实验；尚未证明稳定的记忆效果优势。后续重点是补充各能力之间的连接、改进证据选择，以及在未暴露任务上验证，而不是重新建设同名模块。

这也不等于当前系统已没有工程缺口。已有生命周期保证有范围，语义归属与时间解析仍可能失败，事件组织也可能有误。

## 3. 已有实验提供了什么证据

### 3.1 LoCoMo：已经有标准引用诊断，而且暴露最终选择损失

[生命周期校正报告](SOURCE_EVIDENCE_LIFECYCLE_FIX_2026-09-17.md)基于冻结的开发数据和 304 个检索包重算：

| 可回答题指标 | 结果 |
| --- | ---: |
| 可回答题 / 其中有标准引用题 | 233 / 231 |
| 候选标准引用召回 | 275/309，89.00% |
| 最终标准引用召回 | 225/309，72.82% |
| 多跳题最终标准引用召回 | 55/106，51.89% |
| 多跳题标准引用齐全 | 11/43，25.58% |
| 最终缺失引用分布 | 84 个，其中 67 个已经在候选内 |

这是引用集合的召回与齐全度，不是答案准确率。数据已经用于开发，最终召回未达到当时 80% 目标。它支持的下一步是改善候选进入上下文时的选择和多跳证据组合，而不是认为所有损失都来自缺少 embedding。

此外，`verify_source_evidence_real.py` 已有原生回答、oracle 和 full-source-context 诊断；本轮读取 r2 原始产物，确认 6 次原生回答和 4 条离线诊断（两道题各两个条件）。诊断明确不计入正式得分，模型返回 `supported` 也不是独立准确率审查。因此应扩大和规范已有诊断，而不是再次提出“从零增加正确证据对照”。[脚本](../scripts/verify_source_evidence_real.py)

### 3.2 EgoLife：向量已做，但候选与排序都还有损失

[向量实验](EGOLIFE_VECTOR_RESULTS_2026-09-14.md)使用真实 `text-embedding-v3`，索引 110,384 个来源出现、87,631 个不同文本向量，30 道已暴露问题。

| 路径 | 目标时刻进入硬候选 | 最终 Top-5 命中目标时刻 |
| --- | ---: | ---: |
| Timeline | 4/30 | 0/30 |
| 同池向量重排 | 4/30 | 2/30 |
| 全库向量提名后应用约束 | 8/30 | 2/30 |
| 词法/向量 RRF | 8/30 | 2/30 |

这些是目标时刻代理指标，不是完整答案证据 Recall。结果支持语义召回补入部分词法漏掉的候选，但不支持 RRF 已稳定更优，更不支持换一个向量模型即可解决问题。报告已经建议对比原始短 cue、相邻窗口和时间对齐事件单元；这应继续执行，而不是重复同一组实验后称为新方向。

### 3.3 EgoLife：已经做过真实回答与证据支持对照

[A–D 实验](EGOLIFE_ABCD_MCQ_2026-09-14.md)在共享候选池、同一回答模型下，A 为 27.78%，C 为 32.22%；C 的 29 次正确回答中仅 6 次同时被 Judge 判断为有证据支持，组间差异区间包含零。[原文复测](EGOLIFE_SOURCE_RETEST_2026-09-17.md)A 为 28.89%，S 为 32.22%，但 S 使用约 7.24 倍回答输入 token，也没有证明稳定提升。

每组 90 次是同样 30 题的三个 seed，不是 90 道独立题。两个协议不能拼接；Judge 也有时间解释错误，仍需人工审查。我们已有实验并不是只测接口是否通了，但现有证据还不足以把新检索配置升为默认。

### 3.4 跨会话与复杂记忆：成功和失败都已有

- `jev-memory-20260925-r1/acceptance.json`：真实模型、全新会话召回随机编号，`passed=true`。
- `jev-social-memory-20260925-r1/acceptance.json`：真实模型，带多个人物及嵌套相对日期的提问未恢复约定内容，`passed=false`、`relativeAnchor=false`。

二者本轮均读取了原始 JSON；不能用简单跨会话通过证明复杂时间关系已解决，也不能把复杂失败说成我们完全没有跨会话记忆。

### 3.5 工程验收覆盖了什么

钥匙位置纠正、日记分层与断点恢复、长事件阶段、来源删除级联、任务暂停恢复、说话人合并撤销都有源码、测试定义及历史运行记录。[汇总](EXPERIMENTS_AND_CASES_SUMMARY_2026-09-23.md)

这些验证证明被测链路和边界行为，不能替代事件理解准确率、长期纠错复用率或跨任务成功率。本轮没有重跑它们，不把历史通过数写成当前完整回归结果。

## 4. 真正剩余的差距

### A. 多种表示已有，但查询时还没有充分协同

原文、卡片、近期事件、视觉回看和日记有不同入口与预算；离线向量路径独立。历史事件需要可检索的派生索引，命中后再展开原始证据，不能把日记摘要新增为独立事实证明。查询还需要保留精确字段和相关事件顺序。

### B. 生命周期已有，但“失效”与“修复正确”是两件事

已经可以让旧卡不再 active、来源删除后不再暴露旧答案、日记在依据变化后变 stale。下一步应测：哪些受影响的关联和摘要需要重算，如何避免无关记忆被误伤，以及重算后在不同问法/新会话中能否用对。

这不是第一次实现纠正或级联，而是从分散的防复活措施发展到统一的依赖修复和可验证使用。

### C. 任务可以恢复，但经验还没有变成可验证的方法

重启后回到同一步，与从上次失败中学到新策略不同。后者需要明确成功判据、方法适用范围、失败反例及对照测试；没有可验证结果时不应自动将轨迹晋升为通用技能。

### D. 科研结论缺独立、充分标注的验证

不是缺少实验，而是已有数据多已暴露、题目和参与者有限，指标也有引用召回、时间代理、四选一和模型评审等不同口径。需要冻结新数据及机制变量，保留所有旧组作为回归。

## 5. 下一步应“复用什么、改变什么”

| 顺序 | 复用已有工作 | 新变量及验收问题 |
| --- | --- | --- |
| 1 | SourceIndex、Qwen 向量缓存、候选审计、A–D runner、LoCoMo 引用评分及 oracle 脚本 | 固定预算，比较原文短片段、相邻窗口、带来源事件索引；分别测候选、选择和回答，确定在哪一层改善。 |
| 2 | LongEvents 的 sourceIds、revision、phases 与现有视觉回看 | 让历史事件可按查询提名候选并展开来源；测试时间指代、事件计数和多跳，而不是只向上下文放最近几个事件。 |
| 3 | Timeline supersedes、同来源投影退休、日记 manifest/stale、来源删除依赖 | 统一受影响视图的失效与重建协议；配对测试“接受纠正”和“后续复用”，保留旧历史且阻止旧错误复现。 |
| 4 | TaskSession、Skill、持久工作记录 | 独立验证跨任务约束与中间结果复用；有可靠结果后再研究方法学习，不恢复未经用户要求的工具能力。 |

词法与向量融合已经实验过，不能将“增加 embedding”作为本轮新贡献。事件字段、缺口字段和时间戳也已经存在。更有依据的研究目标是：**这些表示如何共同改善证据选择，以及修订如何可靠影响之后的使用**。

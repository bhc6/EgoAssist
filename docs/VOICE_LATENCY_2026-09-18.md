## 修复

1. 将用量标记为 `persistent-session` 或 `request`。HTTP 文字模型每次重建上下文，其 token 数不再触发 Omni 长连接的压缩和重建，仍完整保留审计与费用数据。
2. 兼容旧日志中没有此标记的 `modular-` 回答。连续 HTTP 请求也不会遮蔽真正的 Omni 用量超限；压缩后重新设置统计边界。
3. HTTP 回答不再累加 Omni 的“25 轮后重连”计数。
4. 压缩时只读取最后一个状态检查点；工具回执查找只读取对应事件类型，避免复制全量音视频日志。
5. 增加 TTS 连接、session ready、首次文本提交、文本提交完成、首次文本到音频的分阶段指标。原来的 `firstAudioMs` 含等待文字生成，不能作为纯合成耗时使用。

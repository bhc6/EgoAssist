# 主动播报被旧免打扰状态拦截

## 原因与使用

本次会话审计发现，一条较早的旧路由分类将普通生活陈述解释为 `assistant / listen / silent`，写入无到期时间的 `interaction.permission.quiet=true`。该状态跨重连和重启保留。`allowReplies=true` 允许主动提问获得本轮回答，但不允许观察触发主动提醒，因此会出现“对话能回答，观察提醒一直暂缓”的情况。

原来的“当前不允许主动播报”没有说明限制来源，还把历史未播出记录说成当前状态。现在页面顶部“语音播报”显示免打扰或等待话语处理，“播报限制与来源”显示触发原话、浏览器本地时间、到期时间；无到期会明确说明。点击“解除免打扰，允许主动播报”后，以后采样满足提醒条件且交互空闲时可以播报。刷新后若实时连接未建立，需点击“连接观察”。

此次没有批量清除历史权限，也没有自动解除实际用户会话的免打扰。普通陈述被旧分类写成持久静音的问题由来源展示揭示，本次未改写所有 `listen / silent` 的既有语义。

## 实现

- `InteractionState.snapshot()` 提供权限来源与当前主动播报限制；来源按权限事件缓存，避免每个音频包扫描历史。
- 新增认证接口 `POST /api/interaction/resume-speech`，携带 `sessionId` 和 `permissionId`。核对账户、会话和权限版本；新语音指令已经更改权限时返回 409，旧页面不能覆盖新设置。解除事件持久化并同步同会话连接。
- 解除按钮在点击手势内恢复 AudioContext。解除免打扰不解除尚未完成的话语处理暂停、不修改观察授权、不重播旧提醒。
- 未通过输出权限的观察审计保存当时权限快照。界面明确区分“当时被拦截”与“现在是否允许”。旧记录没有快照时不伪造当时原因。
- 新画面上下文携带当前 `speechPermission`，包括 UI 解除的时间与来源。模型可以看见解除操作，不再仅看见旧静音原话。提示词区分暂时静音、取消目标、尚未播出和已经发送；新画面仍需重新提供触发证据，实际播放仍由代码检查权限。

## 验证与局限

全量 944 项测试通过，另有 3 条已有 aiohttp 超时参数弃用警告。新增回归覆盖身份隔离、旧权限版本冲突、恢复持久化、保留暂停与观察授权、历史快照不变、当前权限进入新视觉上下文，以及新画面重新产生候选。

真实测试使用独立测试账户、Edge 无头浏览器、EgoLife 的红白格桌布画面、真实路由/视觉/语音服务，没有操作实际用户权限：

| 轮次 | 结果 | 含义 |
| --- | --- | --- |
| 初版 | 失败 | 解除按钮成功，旧提醒没有补播；新画面没有提醒。上下文只包含旧静音原话，缺少 UI 解除操作。 |
| 补充当前权限后 | 失败 | 静音期间视觉模型主动返回无提醒，脚本原先要求必须生成被代码拦截的候选，提前终止；未验证解除后行为。 |
| 修正测试分支后 | 通过 | 本轮确实生成候选并被代码拦截；点击解除后新画面经 `ready → audio-sent → played`，刷新保留解除状态，桌面/390px 手机页面检查通过，无 JS 错误。 |

脚本允许静音期间模型直接不提议提醒，但单独报告 `deliveryGateExercised`，不把模型静默说成代码门槛验证。本次最终值为 true。解除后产生新提醒和浏览器播放回执仍是必需断言，没有因初次失败取消。

一个真实案例通过不代表所有视觉判断稳定；前两轮失败保留。浏览器播放回执不证明扬声器音量或用户确实听到。原始输出和画面保留在本地 `outputs/speech-permission-20260926/`，不提交用户数据；匿名结果见 [验证摘要](validation/speech-permission-20260926.json)。

复现：`python scripts/verify_speech_permission_browser.py --output outputs/speech-permission-new-run`，需要本地服务、已配置真实模型凭据、Edge、Playwright 和脚本指定的本地 EgoLife 素材。

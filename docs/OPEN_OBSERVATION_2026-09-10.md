# 开放环境观察

## 原问题与修复

原默认配置加载 `medication.json`，模型和后端只接受服药及厨房、餐桌、客厅；超出范围会拒绝。界面声称一定澄清、原图不留存，实际 ambient 链路不发澄清，而另一条 SharedScene 链路已经保留部分原图并调用模型。这既限制能力，又造成重复推理和不准确的界面说明。

现在默认加载 `open.json`，没有行为与地点白名单。用户显式配置的专项清单继续采用原有校验，不静默改变专项实验。开放模型输出仅包含自然描述、可见证据、环境描述、疑点、可选澄清和变化提示；不要求自行给置信度，也不依赖行为类别判断。旧数据库接口仍保留兼容字段，不作为概率或类别事实。

每次送检帧保存 SHA256、原始 JPEG、服务器接收/采样时间，日志保留提示词与模型原文。开放模式下可见证据进入 Timeline，疑点放入元数据；时间索引使用采样时间和用户时区。完全相同的相邻证据不重复建卡，所有原始观测仍保留。模型变化标记可能漏掉细节，因此不能决定永久丢弃哪些证据。

无任务且已授权时停用重复的通用后台描述，改为单条开放观察通道；提问时的针对性视觉问答保留。任务中仍使用任务检查点观察，不宣称同时完整记录一切周边活动。默认间隔 5 秒，既有环境变量优先；前端按案例设置 2-120 秒及主动澄清开关，配置和观察结果都可从日志恢复。一次观测有 8 秒响应期限，超时记录失败并释放通道，不伪装成没发生行为。

澄清通过已有记忆草稿和语音输出仲裁处理，不覆盖已有待补充草稿。用户静音时不强行播报。日报、周报、月报使用同一来源收集器，新增视觉来源，按采样时刻归入报告，模型疑点和用户亲述分开表达。

数据为 `data_real/egolife/A1_JAKE_DAY1/DAY1_A1_JAKE_11100000.mp4` 的 3、10、20 秒帧，经实际浏览器 WebSocket 提交到 Qwen，未使用 provider mock。重放时间只证明本次观察到数据集画面，不是原视频发生的现实日期。

最终三帧提交到可见观测结果为 1783.1、1645.3、1712.8 ms；回忆首音频 2641 ms、完整长回答 8386 ms；异步日报 9668.63 ms，四条来源全部纳入，其中三条为视觉观察，引用校验通过。模型仍可能误认包的用途、人物数量或左右手，日志可回看核对。以上是少量样本，不是 P95，也不是眼镜硬件数据。日报真实通过；周报/月报本次仅验证共用的来源与时间范围逻辑，没有另做真实生成测试。真实三帧未触发主动澄清，不能据此声称任意澄清确认流程全部实测。

最终确定性回归 `outputs/open-ambient-tests-final.xml`：444 项通过，0 失败，0 跳过；包含开放范围、缺字段拒绝、JSON 包裹、任务上下文隔离和跨午夜报告时间。旧用例中的模拟 SDK 补齐真实 `update_session` 接口，验证系统与响应使用同一个采样提示词。

```powershell
.venv\Scripts\python.exe -m pytest -q --junitxml=outputs/open-ambient-tests-final.xml
.venv\Scripts\python.exe scripts/run_experiment.py --script verify_open_ambient_real.py --name open-observation --timeout 180
```

采样必然可能漏掉两帧之间的短暂行为；广泛观察不等于任何行为都能准确识别。完整原始产物保留用于进一步人工标注与错误分析，不能将有限测试结果描述成通用行为识别已经完成。

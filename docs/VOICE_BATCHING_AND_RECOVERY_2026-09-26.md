# 快速连续语音批处理与失败恢复

快速连续说话现在按一个短语音批次处理。ASR 可能为同一句话返回多个片段，应用会在最后一个片段后等待默认 **1200 ms** 的静默窗口，再把片段合并成一个持久化 turn，因此 JEV 和回答模型各只处理一次完整输入。

停止、暂停、取消当前回答等明确的输出控制走即时 flush，不等待普通语音窗口；最终控制语义仍由 JEV 判定。新的完整批次会提升语音 floor，取消正在播放的旧回答，并只保留最新回答的播报资格。

批次落盘后才发送带 `turnId` 的 `user_transcript` 事件。这样前端对话记录、审计日志和回答任务指向同一个批次，不会先显示一个没有持久化身份的碎片。

JEV 返回不可用或超时不会静默结束。系统保留原始转写并进入 memory recovery，同时在当前输入仍是最新输入且输出许可允许时播报：

> 我听到了，但理解服务暂时没有响应，请再说一次。

可用环境变量：

- `EGOASSIST_TURN_ACCUMULATE_MS`：普通语音静默窗口，默认 `1200`。
- `EGOASSIST_TURN_QUEUE_CAPACITY`：持久化 turn 队列容量，默认 `64`。

窗口只负责合并 ASR 片段，不会无限等待；达到 `TurnAccumulator.max_chars` 会立即提交。连接关闭时也会 flush 未完成批次。

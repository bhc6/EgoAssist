## 诊断

读取当前实际会话 `.egoassist/users/e157c74e5cea404a/sessions/7ea5c8a1754c4e1a.jsonl`，没有修改原始记录。分析期间会话仍有新输入，初次检查为 43 轮、12 个档案；正式回放输入快照为 58 轮、19 个档案、110 条 scene.turn 版本记录。

- 未发现不同轮次保存完全相同的音频 SHA256。日志中的多条 scene.turn 是同一轮的阶段更新，界面按 turnId 投影，不是 110 次独立发言。本检查不排除内容相似但字节不同的重叠捕获或回声。
- 三对档案的余弦相似度分别为 0.8612、0.7972、0.9487。前两对明确来自同一单声道音频中相互重叠的不同 cluster。模型把同一混合音频区间当作多个说话人的独立声纹提取。
- 原匹配器排除了已被另一个 cluster 使用的档案，然后在剩余候选不足时创建新档案，进一步放大了重复分档。
- 短片段/模型不可用结果被统一覆盖为 mixed-or-unknown，不能清楚表达证据不足。
- 界面直接显示随机 speaker ID；修改名称后，旧发言仍优先显示当时保存的旧名或 ID。

这些证据说明存在建档策略和展示问题，但没有带真实身份标签的录音，不能计算识别准确率，也不能确认全部档案分别属于多少人。

## 修复

1. 跨 cluster 重叠区间保留为 overlapping-speech，不创建档案、不匹配已确认身份。保守处理整个污染片段，暂未实现音源分离或提取其独立干净子区间。
2. 已占用档案仍参与冲突检查；cluster 与声纹相互矛盾时返回未确认，不以新增身份解决矛盾。
3. 保留 unknown/unavailable 及证据不足原因。匹配阈值未调整，避免把降低拒绝率冒充准确率提升。
4. 未命名档案显示“声音 1、声音 2……”；编号按会话内首次档案出现顺序稳定生成，改名与重启不改变其他编号。姓名/称呼仍通过既有持久化身份接口保存。
5. 发言列表、选择框和工作流程使用当前档案名称；历史证据中的原始身份判断不被重写。段数按唯一 turnId 计数，重复版本不增加段数。界面说明档案数不是现场人数。

已有疑似重复档案未自动删除或合并，仍可能影响旧会话的匹配歧义。未确认真实身份前，不能仅凭相似度合并。现有匹配仍使用单个原始样本，跨噪声、距离与设备变化的稳健性尚需带身份标签的评测。

# 视觉答案复用与实际模型阶段

简单看图问题原来先调用视觉模型提取描述，再调用 qwen-flash 改写为回答。现在视觉模型在同一次请求中给出带来源的证据及可选简短答案；通过校验后复用该答案，直接交给 TTS。

| 场景 | 当前处理 |
| --- | --- |
| 无画面的普通文字对话 | JEV 判断 → 文字回答 → TTS |
| 单帧或短时多帧的独立视觉问题 | JEV 判断、视觉请求可并行；视觉答案 → TTS，省去文字改写 |
| 今日统计、历史记忆、任务或复合请求 | 保留取证与综合回答 |
| 视觉答案缺失、来源不合法或没有相应事实 | 回退到原综合回答路径 |

视觉直接回答不等于关闭记忆链路。记忆读取、提交、持久化回答义务、输出许可、轮次与取消检查仍执行。当前麦克风或文字输入都通过已有回答调度器进入播报；不再调用 Omni 生成一次相同内容。原生 Omni 在其他实时对话路径中仍可使用。

## 实现边界

- `visual_question.py` 的单帧与多帧请求返回 JSON。`directAnswer` 必须声明 `visible-only`，有非空短答案、合法帧引用，而且引用必须出现在视觉事实中。来源检查不能证明模型的语义判断完全正确。
- `direct_visual.py` 拒绝记忆查询/写入、技能/任务控制、复合意图、历史画面、后台意图及非回答交互。视觉提示另外排除问候、全天计数、身份推断、建议及依赖外部知识的问题。
- `turn_coordinator.py` 将通过校验的答案保存在 `answer.job.preparedResult`，并作为内部 `preparedAnswer` 交给已有调度器。被打断后，后台补全复用答案，不再次请求模型；原有快照和更正检查保留。
- `modular.py` 直接把已生成文字送入 TTS，不进入 `text_stream`。TTS 失败仍保留文字，取消仍走原有生命周期。回答事件记录真正的视觉模型名称。
- `model_stages.js` 按实际调用记录展示“判断、视觉直接回答、文字回答、语音合成”等阶段，通过 responseId 关联语音事件；配置中的 Omni 名称及 `apiCalls=0` 汇总不作为额外调用。各阶段可能并行，不再用箭头暗示全部串行。
- 可用 `EGOASSIST_DIRECT_VISUAL_ANSWERS=0` 关闭答案复用，保留视觉结构化取证后综合回答。

## 验证记录

全量 pytest 回归通过；新增用例覆盖来源校验、复杂请求回退、无二次文字生成、文字/麦克风入口、取消、TTS 故障、后台恢复及前端模型关联。最终来源门槛修正后相关 28 项回归再次通过。

真实服务使用 EgoLife `A1_JAKE_DAY1/DAY1_A1_JAKE_11100000.mp4` 的画面，测试桌布颜色与纹理。`scripts/verify_direct_visual_real.py` 对相同结构化视觉结果，交错比较两轮“再综合”和“直接播报”：

| 指标（毫秒，中位数） | 再综合 | 直接播报 |
| --- | ---: | ---: |
| 接收到首文字 | 2143.2 | 1750.8 |
| 接收到首音频 | 2384.8 | 1995.0 |
| 接收到完整输出 | 3717.7 | 2911.2 |

直接播报的两次请求均有真实视觉及 TTS 请求，没有文字模型请求。此对照衡量取消二次生成的收益，不是与旧版非结构化视觉提示的完整版本对照；样本很小，不代表所有场景都提速。首音频为 WebSocket 收到音频，不代表硬件已经播放。

另外三项真实边界测试通过：带画面问候回退、今日喝水次数回退、两帧桌布问题直接回答。最初发现模型对问候返回空 evidence 却给 directAnswer 的情况，已通过要求答案引用对应视觉事实修复；失败记录保留。

# 日记档案点击反馈与读取修复

2026-09-26，已部署至本地 8770。

## 定位

正式访问日志显示 13:41 的多次档案点击确实发出了详情请求，响应约需 5–7 秒。原前端在响应前不更新选中项，保留上一份正文；移动端档案列表位于正文下面，打开后也不返回正文位置。因此点击缺少可见反馈。

该账户四份历史档案都已为 `stale`，正文此前已因依据失效撤下。每次读取仍会扫描约 180 MB 会话历史检查指纹，虽然失效档案不能靠重新读取恢复。三个条目还是同一天的不同版本，最终页面更难看出切换。此次没有恢复旧正文或改写用户档案。

## 改动

- 点击立即更新选中状态，并在阅读区显示该周期、日期及加载提示。取消上一份详情读取，保留代际检查，旧结果不覆盖新选择；同一在途条目不重复请求。
- 初始加载补记期间的用户选择优先于默认打开第一份档案。读取失败显示明确错误和重试入口。
- 成功打开后 URL 保存 `entry`，刷新恢复所选档案。手机点击后滚动至阅读区。
- 已失效档案直接返回失效状态及当前补记，不再重新扫描来源；仍撤下正文、来源副本、中间节点及生成输出。未失效档案继续完整来源核验，删除/更正的防泄漏机制保留。
- 明确说明旧正文已撤下，提供“重新整理”创建新版本。静态资源版本同步更新。

# 记忆科研文献矩阵：问题、数据、机制与证据

核验日期：2026-09-27。范围：通用长期交互记忆，覆盖生活、工作、多人关系、持续事件与任务；不限定助老。本文补充[前十五篇论文分析](MEMORY_PAPER_FINDINGS_2026-09-27.md)，扩展到 19 篇，并与[已有实现核查](MEMORY_PAPERS_VS_IMPLEMENTATION_2026-09-27.md)及[实验计划](MEMORY_EXPERIMENT_PLAN_2026-09-27.md)配套。

**证据等级：**“对照结果”说明整体配置表现；“消融证据”较直接支持被移除组件在该设置中的作用；“机制解释”是作者解释或我们的推断，不能把它写成已证实的因果结论。下列结果均来自作者报告，我们没有复现这些论文。不要跨论文按分数排榜。

正文来自 arXiv 官方 HTML；书目信息另从官方摘要页的 citation metadata 核验。链接、获取时间、正文哈希、作者及版本记录见[来源清单](MEMORY_PAPER_SOURCES_2026-09-27.json)，可引用条目见 [BibTeX](references/memory_research_2026-09-27.bib)。未指定版本的 arXiv URL 可能变化，复现时必须固定论文、仓库 commit 和数据哈希。

## 1. 先回答：到底要解决什么科研问题

已有论文分别研究了存储压缩、事实提取、时间更新、图关联、检索路由和经验学习。**这些不是空白领域；我们现有三链路结构也不是直接的算法新颖性证据。**

更有依据的候选问题是：持续到来的信息会改变原有事实和派生摘要；当回答预算有限时，系统如何取得**足够完整、在提问时有效、可追溯到原始来源**的证据，并控制维护这些证据的成本？

这里有三个张力：

1. **压缩与可回答性：**浓缩表示更便宜，却可能丢失人物、先后关系、否定、精确值和多跳连接。
2. **更新与历史保留：**当前答案需要新状态，过去时点的问题仍需要旧状态；“记录变化”和“纠正原记录错误”不能同样处理。
3. **维护与读取：**全量重建可能更稳但昂贵；只隐藏旧摘要便宜，却不保证后续能答对；按需修复又可能增加在线延迟。

这是待实验验证的研究定位，不能预先宣称第一、领先或已经解决。

## 3. 为什么会涨点：哪些机制有证据

### P1：LightMem-Ego——连接完整，不等于机制已经最优

痛点是连续声画转成可回答的生活记忆。系统用共享时间线、微事件和后台整理连接采集与长期问答。自建任务人工准确率整体 55.6%、对话回忆 33.3%；整体 Recall@5 为 77.8%。这些是自身任务结果，没有用统一数据证明胜过 EgoAssist；也没有足够的逐组件对照把收益归因于“三层”。其局限包含上游识别误差和修订/合并/遗忘策略不足。借鉴其事件链路，不能复制结构名称就当创新。[P1，评测表及限制]

### P2：LightMem——减少重复处理，必须看成本边界

痛点是逐轮提取、逐条更新造成记忆构建开销。预压缩、主题缓冲、批处理和 sleep-time 更新减少重复 token 和调用；论文有压缩比例、主题切分及更新方式分析。LoCoMo / GPT-4o-mini 中，LightMem `(0.8,768)` 配置报告 72.99% accuracy、构建 token 85.19k；Mem0 对应 61.69%、1693.39k。**这不是我们可直接复用的预期涨点，也不是整个系统成本。**需同配置读取效果与成本，不能拼接各行最优数；FullText 空白成本字段不是零成本。[P2，表 3、图 3、附录 A]

### P3：LongMemEval——把记忆失败拆成索引、检索和阅读

痛点是记住片段仍答不对长期问题。原文值保留、事实扩展索引键能改善查询匹配；时间查询缩小范围；阅读策略影响证据使用。表 3 的 M / round 设置中，原文 key 与原文+fact key 的 Recall@5 为 0.582 / 0.644，支持“改善入口而非只替换为摘要”。表 4 显示时间扩展受解析模型影响，并非所有模型都提升。我们必须比较原文 RRF 加事实键与时间扩展，不能仅胜过弱词法基线。[P3，§5、表 3–4]

### P4：HippoRAG 2——关系入口和原文连接共同重要

痛点是单段相似检索不能找齐多跳支持。完整 query 对三元组链接、过滤和 passage 节点配合图传播。表 4 多跳平均 Recall@5：完整设计 87.1，去 passage 节点 81.0，query→node 59.6。这是较直接的组件证据，但不说明任意图都有收益。我们的候选方案应对照相邻窗口与 MMR，验证事件关系是否真补齐证据；不要把共现标签网络冒充同等图检索。[P4，表 4]

### P5：A-MEM——关联与后续演化可改善多跳记忆

痛点是孤立笔记难以被后续相关事件重新组织。以内容/关键词/上下文生成 note 并链接、更新旧记忆。表 3 的多跳 F1：去 LG 和 ME 为 9.65，仅去 ME 为 21.35，完整为 27.02；支持两模块在被测设置中的作用。评价是 F1/BLEU 等，不等于支持证据正确率；演化也可能传播错误。我们应测新事件帮助历史召回，同时检测无关旧记忆被误改的比例。[P5，§4、表 3]

### P6：Mem0——提取与选择性更新优于无限堆历史的条件性证据

痛点是把全部对话塞进上下文的成本和干扰；方法抽取重要事实，比较已有记忆后增/改/删，并研究关系图变体。LoCoMo 对照支持该设置的效用，但类别排除、judge 和 reader 配置决定比较口径。图版本没有可外推为“任何任务都更好”的依据。启发是把更新动作、事实去重和关系使用分别测，而不是把 CRUD 的存在本身作为科研贡献。[P6，实验与图变体分析]

### P7 / P8：LoCoMo 与 EgoLife——数据构造决定记忆难题

LoCoMo 强调长程对话、时间与跨会话联系；人工校验降低生成错误，但无法完全等价真实连续生活，视觉素材也不保证稳定的人物/家庭身份。EgoLife 则把长时间、多人物、视听变化带入问题，感知遗漏与检索遗漏都可能致错。两者不能共用一个含糊“记忆准确率”。我们应先固定官方描述测记忆，再单列原始媒体感知轨；可回答性标注必须与模型真正能看到的输入一致。[P7, P8，数据构造与实验]

### P9：StreamMemBench——保存反馈不等于后续能用

痛点是静态 QA 看不到交互后的学习。四个指标分别定位保留、初用、反馈吸收和后续复用。附录 D 对同一检查点进行 commit / no-commit 配对；160 条轨迹宏平均 FUR 由 27.5% 到 40.6%，支持提交交互有作用，但依然存在较大缺口。论文与仓库版本的轨迹数量、backbone 描述有差异，必须固定版本；我们不能把“字段保存成功”当 FUR 已提高。[P9，附录 D]

### P10 / P19：Memᵖ 与 ReasoningBank——方法知识不同于事实记忆

前者比较任务轨迹、抽象脚本及组合，并用任务结果修订；后者从成功和失败中抽取策略。ReasoningBank 的 WebArena-Shopping 失败轨迹消融为 46.5→49.7，支持把失败转为可用策略，而非简单追加失败原文。其附录 C.2 总 token 为无记忆 50,847.4、ReasoningBank 53,054.5：步骤少了，总 token 仍约增加 4.3%；MaTTS 额外采样也必须计入。我们的 TaskSession/Skills 是载体，尚不等于自动学会方法。该方向价值高，但首篇不宜同时包揽。[P10，实验；P19，图 7、表 5]

### P11 / P12：MemoryArena 与 MemoryAgentBench——能力之间存在取舍

MemoryArena 让后一会话依赖前一任务的约束/产物，检查点恢复不能替代真实完成。MemoryAgentBench 用增量输入分别测精确召回、测试时学习、长程理解和选择性遗忘：RAG、全上下文及记忆 agent 在不同能力上表现不同；top-k 相同而 chunk 不同也会造成预算不公平。不能用一个平均数断言系统全面优越。我们应选择与主张相关的子任务，并保留长上下文、低成本原文检索作为强参照。[P11, P12，实验及能力分解]

### P13–P15：可引用的背景，不是本轮必须复现的基线

Voyager 的可执行技能、反馈与自验证提供程序记忆范例；Generative Agents 的反思/计划面向沙盒行为可信度；Titans 在模型内部更新神经记忆参数。它们分别回答行动复用、行为生成与模型容量问题，与外部 API 上的证据选择不是同一实验。引用应解释研究边界，不把这些能力全加进产品以凑系统复杂度。[P13–P15，方法与实验]

### P16：Zep——时间图、原始 episode 与失效关系都已有先例

痛点是事实会变化且问法不同。Zep 保留原始 episode，抽取实体关系与有效时间，混合检索、重排，并将冲突边失效。LongMemEval-S / GPT-4o-mini 报告 full-context 55.4%、Zep 63.8%，上下文约 115k / 1.6k；这是系统对照，没有隔离各组件的全部贡献。DMR 已接近饱和（98.0 / 98.2），不能作为决定性提升证据。**“时间戳+图+更新”无法成为我们的独占创新。**Graphiti 当前代码也不自动等于论文中的完整 Zep 系统。[P16，§2–4、表 1–3]

### P17：AriGraph——事件与语义环境知识共同服务行动

痛点是非结构化历史难支撑环境探索，位置变化又使旧事实误导规划。方法结合事件与语义图，检索关系及原始观察，并更新过时状态。其任务分析显示清扫与烹饪对事件记忆的需求不同；不能据此断言图在每类任务上都降本。TextWorld 的五次运行取最好三次平均是选择性汇总，我们应报全部运行。它已经覆盖动态环境图和事件来源连接，后续工作必须明确超出何处。[P17，§4–5、附录 D]

### P18：Adaptive-RAG——选择检索强度已是成熟研究问题

痛点是对简单题一律多步检索浪费，对难题一律一次检索不足。训练分类器在不检索/单步/多步间选择；监督结合模型结果与数据类型先验，含分类监督消融和 oracle 路由。效果说明预算应该适应任务，但 oracle 不是可部署成绩。我们用 JEV 做有限判断属于工程实现；除非证明新决策目标、校准或策略优于合理基线，否则不单列为算法创新。[P18，表 1–4]

代码与原始结果的路径见[实现核查](MEMORY_PAPERS_VS_IMPLEMENTATION_2026-09-27.md)。重要证据是：

## 5. 论文需要正面讨论的核心问题

1. **记忆单元按存储方便定义，还是按可回答性定义？**事件可能把支持放在一起，也可能错合并。必须与短片段、相邻窗口在同预算比较。
2. **检索相似与证据充分是否是同一目标？**多跳题可能需要相似度低的桥接事实。最终选择不能仅看单条分数，但“证据齐全”的 oracle 标签只可评分，不能喂给选择器。
3. **当前事实、历史事实、曾经误信的事实如何区分？**状态改变、纠错和迟到信息需要不同时间语义；不能统一删除旧值。
4. **节省的是在线成本还是总成本？**后台整理、抽取、embedding、失败重试、存储和多次读写都应计入；还要看一个记忆被复用多少次才回本。
5. **观察不到，是否意味着没发生？**采样缺口只支持“不知道”，不支持零次数；已有 coverage 字段需要实际进入检索和回答判断。
6. **算法创新还是系统组合？**若收益只来自接上已有接口，应定位可复现系统研究；只有明确的新机制、强基线和消融支持，才升级算法贡献主张。

## 6. 引用优先级与复现范围

首篇必须认真比较 P2/P3/P16，解释与 P4/P5/P17/P18 的差异，使用 P8/P12 的任务设计；P9 用于反馈扩展。P1 是最相近的生活系统参考，但其自建演示数据不可获得时不能假造同基准复现。P10/P11/P19 放在程序性与任务复用讨论；P13–P15 提供历史和路线边界。

我们不需要复现全部 19 篇。主计划选择生产基线、BM25、RRF、事实键/时间扩展、Graphiti、LightMem、全上下文和候选方法；官方版本与固定组件版本分开标记。详细样本数、消融、指标、预算及失败后的收缩主张见[实验计划](MEMORY_EXPERIMENT_PLAN_2026-09-27.md)。

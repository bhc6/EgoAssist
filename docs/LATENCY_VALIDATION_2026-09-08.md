# 路由延迟与超时修复：2026-09-08

本次只处理实时链路的主要串行等待和路由超时生命周期。没有调长原有 3 秒路由截止时间，没有跳过记忆，也没有用模拟模型代替真实延迟验收。

## 修复

- 将路由 API 的 17 字段完整输出改成带版本标记的稀疏 JSON：普通对话只需 `{"v":1}`，记忆不再重复输出原子和旧版 memoryText 等字段。服务端补齐默认值，再执行原有字段、范围、技能和意图校验。运行时与前端仍接收完整标签；旧格式兼容。
- 使用可复用连接的原生 aiohttp 请求代替生产路径中的同步 SDK HTTP 线程。路由超时或上游取消会取消本地 HTTP 等待并释放连接，不再留下正在等待 API 的执行器线程。WebSocket 结束时关闭所属路由客户端。取消本地请求不保证供应商已经停止计算。
- 当前用户输入与历史上下文分开传递，明确字段类型、原始语言及少量协议示例，避免压缩输出后出现布尔 consent、翻译实体导致漏召回等问题。
- 日志记录 HTTP 状态、request ID、token usage、错误类型及 `timedOut`，不再只留下空的 TimeoutError 文本。

## 真实结果

同一台机器、同一个 `qwen-flash` API、相同 8 类输入：普通对话、显式保存、记忆查询、停止、否定停止、技能选择、复合提醒、待补充记忆。按顺序执行，未并发灌流量；不同轮次仍受网络和服务缓存影响，不能作为严格的随机交错 A/B 测试。

| 独立路由 | 修改前（16 次） | 最终版本（40 次） |
| --- | ---: | ---: |
| 行为检查通过 | 12/16 | 40/40 |
| unavailable/超时 | 0 | 0 |
| 中位耗时 | 1302.6 ms | 397.6 ms |
| 样本 P95（nearest rank） | 2327.0 ms | 869.2 ms |
| 最大耗时 | 2327.0 ms | 2050.5 ms |

修改前这批基线恰好没有超时；此前已保存的真实两轮记忆日志存在两次约 3 秒路由超时，见旧验收记录。本次最终 40 次独立路由和以下 9 次端到端路由均无超时，不等于承诺网络或供应商永不超时。基线 4 个失败是语义/格式错误，不能算作超时。

生产 `create_app` + 真实 Qwen Realtime 完整验收：每次验证真实音频、完整字幕、持久化 `response.done`；记忆还必须证明已提交卡片被召回且答案包含正确值。路由 fallback 直接判为失败。

| 三次重复端到端验收 | 首音频样本 | 中位数 |
| --- | --- | ---: |
| 普通对话 | 855 / 784 / 985 ms | 855 ms |
| 记忆查询 | 1210 / 1174 / 1250 ms | 1210 ms |

普通对话与两轮记忆共六组全部通过。保存阶段返回文字回执，查询阶段有真实语音。对照上一版普通对话 1.55–2.06 秒、记忆查询 3.61–3.93 秒，本轮首音频明显下降。

计时从发送完整文本 control 到收到首个音频包，**不包含麦克风采集、ASR 和扬声器播放耗时**。单独建连样本为 240–3263 ms；慢样本主要在对话 WebSocket 建连，随后视觉连接约 109 ms。首次联网仍可能有波动，这不是每轮路由耗时，也未被隐藏在指标中。

# 喝水提醒未播报：时效门槛与音频初始化

## 原始故障

用户配置“喝水时提醒”。原会话 14:50:02 的已接受观察明确识别到瓶口靠近嘴部的饮水动作，模型产生 `requested-reminder` 并引用已保存目标 `g1`。但画面年龄为 9512 ms，超过统一的 5000 ms 现场播报门槛；审计结果为 `deferred / stale-frame`，没有进入语音发送。之后几个候选也因同一门槛被拦下。

同时发现“连接观察”入口只建立实时连接，不初始化 AudioContext；`playPcm24` 在音频上下文不存在时直接返回。因此即便提醒通过服务端门槛，仅使用观察入口的页面仍可能无声。

## 修改

- 用户明确要求的事件提醒使用独立窗口 `EGOASSIST_REQUESTED_REMINDER_MAX_AGE_MS=20000`，可配置上限 60000；现场危险、一般目标帮助、澄清仍沿用原实时窗口。
- 观察接收、交互判断及首次输出前的权限检查使用相同窗口。超期仍不启动播报；开始后可正常说完，授权、目标变化、忙碌和重复提醒检查保持有效。
- 用户事件提醒要求表述为“刚才看到”，不把采样事实当作仍在发生。视觉提示词明确拿着瓶子不等于喝水，已请求提醒不应再询问是否需要提醒。
- “连接观察”按钮在用户点击时初始化并恢复音频上下文，不需要开启麦克风即可播放提醒。

## 验证与限制

84 项观察、提醒及链路隔离测试通过，另 45 项实时 API 测试通过。新增检查覆盖约 9.5 秒的已请求事件可提醒、20 秒以外禁止、危险/一般帮助/澄清不放宽。

原采样帧重新调用视觉模型时，两次遇到 8 秒超时，诊断性延长至 20 秒的一次请求返回 `InternalError.Algo.ModelServingError.IrrecoverableModelError`；EgoLife 帧也返回同一内部错误。未将此视为视觉验收通过，未据此修改生产视觉超时或切换模型。

独立重放原来保存的视觉输出，移除隔离账号没有的历史记忆比较引用，并注入 9.5 秒结果延迟；真实语音模型及 Edge 浏览器经过 `ready → audio-sent → played`，收到设备播放回执。重复画面未重复播报，停止观察后普通对话仍正常。阴性与关闭提醒分支在此重放里为模拟条件，不作为真实视觉识别证据。

重放旧视觉候选时，播报结果虽有“刚才看到”，仍沿用了候选中的询问句。随后本地正式服务上，新视觉提示词成功识别原喝水帧，约 2498.6 ms 产生候选；真实语音为“刚才看到您正在喝水。”，取得浏览器 `played` 回执。重复帧未重播，不匹配目标和关闭提醒均未触发。浏览器播放回执不等于测量用户实际扬声器音量。

正式服务验收脚本的上述提醒检查通过，但随后附加的“停止后计算九乘九”检查因 `routing-unavailable` 失败，报告整体 `passed=false`；不能把整个脚本说成全通过。隔离重放中的同一附加对话检查通过。正式服务报告为 `outputs/drinking-reminder-production-20260926/report.json`，其中 `browserPlaybackConfirmed=true`。这表明本次提醒链路修复有效，外部模型/路由仍有间歇可用性问题。

# 长事件与声纹档案优化

## 交付行为

开放环境观察现在将已保存的画面观察与用户输入按时间整理成事件：独立事件 ID、阶段、进行/暂停/完成/待确认状态、原始来源引用、证据覆盖跨度与缺口。页面新增“事件回顾”，可以整理已有记录、失败重试、从原始证据重新整理，并分页查看依据和原始图片。

整理是独立异步任务，不阻塞每帧观察或回答。默认 qwen-flash，每批最多 24 条来源、最多 16 个事件更新，每次自动任务最多连续处理三批，仍有积压则间隔 20 秒继续；单次模型请求限时 30 秒，连续三次失败暂停自动重试，保留原始证据待手动重试。历史任务状态、源 ID 和派生结果持久化在当前会话 journal，重新加载时可恢复。完整请求、原始响应、提供商请求 ID、usage、失败原因可审计。

跨批更新必须引用新证据；引用旧阶段而没有新证据的输出作为无更新处理，并记入 ignoredWithoutNewEvidence；未知引用拒绝提交。模型不能自行指定新事件 ID、时间或持续时长。超过 30 分钟的来源间隔分批处理，超出该窗口的旧事件不会参与自动延续。该保守规则可能将一次长暂停的真实活动分成两个事件，目前没有人工合并事件入口。

事件视图区分最后有证据的状态与当前状态，超过 30 秒没有新证据显示提醒；短间隔采样也不证明持续看见。continuousDurationSeconds 始终未知，evidenceSpanSeconds 只表示首末引用跨度。每条来源和事件时间使用原始时间；当前问题只读取提问前已经生成的事件，避免未来证据进入回答。派生层不替换原文，原文被删除时事件及其回答依赖也随之失效。

文字、语音及后台回答通过既有 sharedScene 上下文获取同一事件投影。回答上下文最多六个事件、每事件四条原文摘录，页面默认最近十二个事件及每事件十二条来源，截断明确标注；完整原文从当前账户、当前会话的分页接口读取。事件层仍是辅助推断，不能证明模型理解完全正确，也不等于完整一天的无遗漏录像理解。

个人日记保留独立队列和存储，仅在读取原始来源时附上可重建的事件阶段提示；不增加独立“事实来源”，不改写原始记录。日记测试继续通过。

## 声纹

- 延续上一轮重叠单声道不建档与 cluster 冲突保护，识别出历史上以重叠片段创建的档案，不再把这些混合样本用于新身份匹配。档案和语音仍保留，界面明确提示。
- 默认名称仍为“声音 1、声音 2……”；增加最多两段原始语音试听，疑似重复提示仅作线索，不自动归并身份。
- 用户可选择“要归并的声音”和“保留称呼与身份”，确认同一人后合并。归并关系作为追加日志保存，不删除声纹向量、音频、原始身份判断或历史发言。
- 匹配时按归并后的身份聚合多个有效样本，不让同一人的多个样本互相竞争造成置信差不足。历史展示使用当前称呼；发言计数按唯一 turnId，归并不会重复计数。
- 支持链式合并与按最近一次顺序撤销；禁止自合并、循环、未知档案、跨账户操作。撤销恢复原档案与称呼。没有在用户真实会话自动合并任何身份。
- 相似度不是身份真值。环境噪声、短语音、回声和跨设备差异仍可能造成分档或未知状态；没有宣称声纹准确率提高到某个数值。

## 实测

1. **真实会话记录 + 真实模型 + 浏览器问答**：`outputs/events-speakers-20260918-r5/report.json`。复制当前真实会话的来源和媒体到隔离应用，7 次事件模型调用完成整理，浏览器改名、合并、刷新恢复、撤销通过；浏览器文字提问产生完成回答。answer.job.context.sharedScene.longEvents 实际包含 6 个事件。这个测试重用已保存的真实观察与转写，不是新拍摄或重新进行视觉识别。
2. **最终界面与证据分页**：`outputs/events-speakers-browser-20260918-r3/report.json`。明确复用上一步的派生证据快照，模型调用数为 0；验证分页读取原文、历史改名、合并撤销、刷新恢复，桌面/手机无横向溢出、无页面异常，截图同目录。合并仅发生在隔离副本，不能据此认定测试用的两份真实声音属于同一人。
3. **生命周期**：`outputs/long-event-stages-20260918-r1/report.json`。明确标注为模拟观察文本，调用真实模型五次，验证开始做饭、暂停、重启组件后恢复、完成、另一次做饭。保留同一事件四阶段，另一次活动创建新事件，有断档且连续时长仍为 null。不是物理媒体测试。
4. **当前实际会话已持久化**：`outputs/long-events-live-20260918-r1/result.json`。直接读取并追加派生记录到当前会话，完成两条事件、待整理来源为 0；分别有 4 和 3 个阶段，引用 41 和 54 条来源，证据跨度约 375 和 446 秒。原始记录不改写；事件数量是本次模型归组结果，不是唯一标准答案。
5. **回归**：`outputs/events-speakers-regression-20260918-r2.xml`，728 项通过、0 失败/错误/跳过。随后新增自动失败上限的定向验证：`outputs/events-speakers-focused-20260918-final.xml`，41 项通过。包括日记隔离、来源删除级联、伪造引用拒绝、长断档、状态恢复、身份合并撤销与权限。

## 保留的失败与限制

- r1 过于要求明确目标，真实办公室观察全部被跳过；改为允许保守的可见活动片段与待确认状态。
- r2 拒绝模型引用旧阶段；现允许引用当前事件已有来源，但必须有新来源才能更新。
- r3 事件整理和合并恢复通过，长篇浏览器回答触发既有 45 秒播报完成看门狗，复制的未完成旧 turn_inbox 还引发无关恢复任务。后续测试不复制未完成工作队列，提问明确限字；**长篇播报超时未在本次重新设计**，不能把简短问答通过解释为任意长度播报都可靠。
- r4 模型仅重复旧事件被整批拒绝；现对旧来源且无新证据的更新作可审计忽略，其他未知引用仍拒绝。
- 最终 UI 回放前两次分别因复用快照带入了未整理的新测试问题、及测试假定未改名前名称而停止；修正测试准备后 r3 通过，原目录保留。
- 事件摘要仍可能有错误推断，用户应能直接检查来源。模型本轮对同一记录的事件粒度有变化，因此不报告“长事件识别准确率”。
- 当前实现按会话跟踪，未做跨会话人物自动识别、跨天事件自动连接或整日连续视听验收。

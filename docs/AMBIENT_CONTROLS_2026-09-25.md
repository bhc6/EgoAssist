# 后台环境观察：作用、控制与停止边界

日期：2026-09-25

## 功能定位

界面将“开放环境观察”改为“后台环境观察”。用户授权后，在实时会话持续收到画面时，按间隔分析采样帧，保存带来源与采集时间的观察，供现场问答、记忆整理和日记使用。没有摄像头画面或实时连接时，授权本身不会产生观察。

它属于三链路中的观察链路：提供现场证据和待确认疑点。交互链路负责用户问题与输出调度，记忆链路负责持久化、整理和检索。观察推断不等于用户确认事实，也不自动执行任务。一次采样不能证明间隔内一直可见；没有观察记录不能推断事情没有发生。

新会话默认安静记录（`questionsEnabled=false`）。用户可开启“允许空闲时主动澄清”，使符合条件的观察疑点进入原有澄清与语音调度流程。已有会话保存过的设置继续生效。

## 用户操作与生效范围

| 操作 | 范围和结果 |
| --- | --- |
| 授权开启 | 账号级，适用于该账号全部会话；仍需各会话的实时连接与画面输入 |
| 应用设置 | 当前会话；保存观察间隔、主动澄清开关和澄清最短间隔 |
| 停止后台观察 | 撤销账号观察授权，停止全部会话的后台采样分析、丢弃待分析帧并取消观察来源的待播澄清 |
| 关闭主动澄清 | 当前会话继续安静观察，取消观察来源的待播问题 |

停止后保留已保存的记录、设备连接和用户主动问答。任务中的画面核对和用户主动看图提问仍可调用视觉能力；因此“停止后台观察”不是关闭摄像头或禁止所有视觉请求。关闭设备仍使用设备设置。

界面固定保留开启/停止按钮；频率设置和最近观察依据按需展开。状态区分已停止、等待连接、等待画面、正在分析、正常采样及服务异常，提供设备设置入口。保存失败保留草稿并允许重试；轮询不覆盖未保存输入。

## 本次修复的实际缺陷

1. 旧版轮询重建整段 HTML，输入框失焦后会用服务器旧值覆盖草稿，造成“应用”无效。
2. 停止分支绕过 disclosure HTML 缓存；再次开启时缓存误判无需渲染，随后对不存在的按钮绑定 `onclick`，出现 `Cannot set properties of null`。
3. 控制接口缺少完整状态回执和版本，旧轮询响应可能覆盖刚完成的操作。现在返回完整快照，用进程 epoch 和账号递增 revision 阻止旧响应回滚状态，并串行处理同账号的控制操作、向在线会话广播。
4. 撤销授权原先只移除了观察会话对象，没有关闭视觉 provider 或清理等待帧。现在使回调 generation 失效、清空活动与待处理帧、关闭观察连接；重新授权后按新需求恢复。
5. 原实时接入在后台观察关闭时反而启用了 `SharedScene.append_frame(describe=True)`，继续自动描述画面。现在接收帧只缓存证据，自动分析统一由授权观察链路发起；主动视觉问答仍按问题执行。
6. 观察来源语音在发出时重新核对授权、会话 context 和 generation；取消仅针对观察请求。WebAudio 定向停止观察音频；LiveKit 清理观察输出队列，并再次检查等待期间发生的撤权，保留用户回答。

关键代码：`console/ambient.js` 管理稳定控件、草稿和异步操作；`application/composition.py` 管理控制状态；`application/realtime_connection.py` 管理帧接入与输出权限；`realtime/omni.py` 管理观察生命周期；`realtime/livekit_transport.py` 管理语音队列边界。

# 三链路交叉参考与主动澄清验收

## 实现与证据边界

观察、交互、记忆通过证据互相参考，不采用多模型投票，也不把模型置信度当作事实概率。已有环境观察请求同时返回可见证据和可选历史比对，不新增一次比较模型调用。语义路由沿用现有调用处理用户纠正，SQLite 提交不等待额外 LLM。

- `runtime.py`：提供同用户、同案例的近期发言和记忆，包括 participant 范围；限制条数，冻结请求快照。
- `realtime/observation_reviews.py`：校验引用、时间、证据序号；记录比对假设与提问状态，重启后由日志重建。
- `realtime/perception.py`：模型使用请求内的 `u1`、`m1` 短引用，服务端按该快照映射回原始 ID。原始模型输出与标准化引用同时保留。
- `realtime/scene.py`：问题保留当时可用的观察和比较快照；后到画面不覆盖旧问题。
- `realtime/semantic.py`、`memory/timeline.py`：用户明确纠正时按候选记忆 ID 修订，旧卡退出 active，新卡携带 `supersedes`，事务失败全部回滚。
- `console/app.js`：展示比较理由、帧时间、引用与校验原文、暂缓原因、音频发送和设备播放状态。

可选比较格式错误不再使整帧可见证据丢失。不存在的来源、晚于画面的引用、非法证据序号、同帧充当独立证据会阻止该候选提问。原话与其派生记忆合并来源根，不能算两票；当前只展开直接来源，不是完整的来源图推理。

## 澄清与修订

提问经历 `ready → audio-sent → played → closed`；未实际发送音频时不创建待确认草稿。`played` 仅表示设备报告开始播放，`closed` 表示草稿已处理或过期，均不等于用户确认了事实。忙碌、静音、旧帧、已有草稿和冷却期会暂缓，下一次新鲜观察再判断。没有额外的离线澄清重放进程。

模型使用 `follow_up_of` 指向已提供的候选来关联不同措辞；相同问题结合场景变化和帧校验值进行后备去重。已发送记录与冷却期从追加日志恢复，不会因刷新或超过 64 帧而丢失。默认最短提问间隔 90 秒，可在前端改为 1–3600 秒，环境变量为 `EGOASSIST_AMBIENT_QUESTION_COOLDOWN`。新变化仍可产生新的事项。

修订目标来自观察快照的 `memoryCandidates`，不能使用原话事件 ID 冒充记忆卡 ID。支持明确纠正 fact/state/preference，或只有 event 卡表示的旧陈述；修订结果生成 fact/state/preference。当前限制同用户、同案例、同范围，保持原始日志和旧版本。模型无法选择明确目标时仍需要澄清，不能自动任意覆盖。

## 真实测试

供应商为真实 Qwen，浏览器为 Edge；视频来自 `data_real/egolife/A1_JAKE_DAY1/DAY1_A1_JAKE_11100000.mp4`。测试使用真实视频帧和人为设计的中文交互，不是未经干预的自然对话数据集，也不测量眼镜硬件或麦克风 ASR。

| 证据目录（位于 `outputs/runs/`） | 结果 |
| --- | --- |
| `cross-lane-real-08` | 比较到前端可见 2349.1 ms；一次主动提问、明确修订、旧目标退出 active、supersedes 关联、刷新不重复通过 |
| `cross-lane-real-09` | 最终短引用提示词通过；比较 2730.0 ms；观察模型两次耗时 2544.3、1608.9 ms；提问经历发送、播放、结束，刷新后记录相符且未再提问 |
| `cross-lane-concurrency-real-01` | 环境观察、任务检查、回答实际重叠；观察到前端 2672.7 ms；突发两问均完成，归属正确 |

并发样本：两问受理回执约 26.2、26.4 ms；专门视觉提取 333.6、470.2 ms，视觉排队均约 1.3 ms；服务器收到问题到完整答案落账约 3194、3583 ms。后两个值不包含眼镜采音、网络上行、完整扬声器播放。样本数量不足以估计 p95 或证明相较旧版的统计显著提升。

474 项回归测试全部通过，JS 语法检查通过。新增测试覆盖引用别名不修改原始快照、非法引用与索引、同源去重、静音/忙碌/冷却、实际音频后建草稿、重启去重，以及修订范围和事务回滚。真实页面在 1440 和 390 像素宽度均无脚本错误或横向溢出，截图见 run09 的 `review-*.png`。

复现时必须使用尚不存在的输出目录，避免覆盖历史：

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe scripts/verify_cross_lane_real.py --output outputs/runs/cross-lane-new
.venv\Scripts\python.exe scripts/verify_observation_lanes_real.py --burst --output outputs/runs/concurrency-new
```

各次运行保存 `report.json`、模型原文、案例追加日志、记忆库和采样媒体；失败报告保存异常。`outputs/` 不提交 Git，需单独归档实际产物。

## 保留的失败与限制

run01 的模型未给有效比对，且观察背景遗漏 participant 记忆；run02 返回空证据索引使整帧失败；run03 音频关联丢失候选 ID；run04 的早期验收只检查新记忆，未发现旧事实仍有效。随后加强断言，run05 暴露错误目标 ID，run06 暴露对事实/事件表示的错误假设，run07 暴露长 ID 抄写错误。对应修复与失败目录均保留，run04 不能视为最终修订验收成功。

run08 清理连接时出现 Windows Proactor `ConnectionResetError`，业务断言通过；run09 未复现。回归另有 aiohttp API 弃用/键类型警告和沙箱 pytest 缓存写入警告，不影响测试结果。

这些机制约束来源和执行，不保证模型语义正确。缺少比较、漏识别同一问题、物体误认和事件时间误解仍可能发生；采样间的动作可能遗漏。持续视频事件分割、多人可靠身份归属、完整来源图、跨案例自动修订和硬件时间同步尚未由本轮实现或验收。三链路并行提供更充分的上下文和更少的相互等待，不承诺每个回答都会更准确。
